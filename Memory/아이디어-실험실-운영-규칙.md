# 💡 아이디어 실험실 운영 규칙

> 목적: 운영 대화와 아이디어 대화를 분리해, 채택된 아이디어를 빠르게 실행 가능한 카드로 전환한다.

## 1) 아이디어 유입 경로

### 경로 A: 일일 브리핑 자동 추출
- 매일 09:00 KST `daily-briefing` 크론이 수익화 아이디어 도출
- `data/briefing_ideas.json`에 저장 → `save_idea.js` 실행
- REPORTS 토픽(29)에 **승인/거절 인라인 버튼** 전송
- 사용자가 버튼 클릭 → 승인(`idea:ok:ID`) 또는 거절(`idea:no:ID`)

### 경로 B: 운영 메인에서 수동 승격
- 운영 메인(31)에서 대화 중 아이디어가 나오면
- 에이전트가 요약 정리 → `save_idea.js` 실행
- 동일하게 버튼으로 승인/거절 결정
- "이거 채택", "실험실로 보내" 등 문구도 동일 처리

---

## 2) 토픽 역할

| 토픽 | ID | 역할 |
|------|-----|------|
| REPORTS | 29 | 아이디어 버튼 표시 (승인/거절 선택) |
| 운영 메인 | 31 | 의사결정, 크론/장애/우선순위, 수동 아이디어 승격 |
| 아이디어 실험실 | 177 | 승인된 아이디어의 3인 토론 + 실행 카드 생성 |

---

## 3) 아이디어 처리 플로우

```
아이디어 감지 (브리핑/대화)
    ↓
save_idea.js → pending_ideas.json + 텔레그램 버튼
    ↓
사용자 버튼 클릭
    ├── 승인 (idea:ok:ID)
    │   ↓
    │   process_idea.js --approve ID
    │   ↓
    │   토픽 177에 실험 시작 알림 (또는 대기열)
    │   ↓
    │   4단계 AI 토론 (3인 분석 + 악마의 변호인, 약 30분)
    │   ↓
    │   아이디어 카드 생성 → 토픽 177 + vault 저장
    │
    ├── 대기열 (idea:queue:ID)
    │   ↓
    │   process_idea.js --queue ID
    │
    └── 거절 (idea:no:ID)
        ↓
        process_idea.js --reject ID --reason "사유"
        ↓
        거절 사유 분석 + REPORTS 토픽에 결과 보고
```

## 4) 4인 AI 토론 프로세스 (3인 분석 + 악마의 변호인)

승인된 아이디어에 대해 4단계 순차 분석:

| 순서 | 역할 | 에이전트 | 분석 항목 |
|------|------|---------|----------|
| 1 | 📡 트렌드 분석가 | trend-scout | 시장 수요, 경쟁 현황, 타이밍 |
| 2 | 🛠️ 기술 엔지니어 | ops-dev | 실현 가능성, MVP 범위, 추가 개발 |
| 3 | 💼 비즈니스 기획자 | main/biz-writer | 수익 모델, KPI, 7일 실행안 |
| 4 | 😈 악마의 변호인 | main | 치명적 결함, 시장/실행 리스크, 유사 실패 |

> **판정 규칙:** 3인 분석 + critic. critic이 "반대"하면 최종 판정 1단계 강제 하향.
> 예: 강력추천 → 조건부추천, 추천 → 보류, 보류 → 반대

단일 세션 파일: `data/idea_sessions/{ID}.json`
- 에이전트는 JSON 분석만 생성 → 오케스트레이터(`run_idea_discussion.js`)가 카드/텔레그램/vault 처리

## 5) 아이디어 카드 템플릿

토론 결과를 종합하여 토픽 177에 전송 + vault 저장:

```markdown
🧪 아이디어 실험 결과 — {제목}

📌 한 줄 요약: {summary}

📡 시장 분석 (trend-scout)
• 수요: {demand}
• 경쟁: {competition}
• 타이밍: {timing}

🛠️ 기술 분석 (ops-dev)
• 실현 가능성: {feasibility}
• MVP 범위: {mvp_scope}
• 추가 개발: {dev_needed}

💼 비즈니스 분석 (biz-writer)
• 수익 모델: {model}
• 예상 KPI: {kpi}

🔥 7일 실행안
• Day1: {step1}
• Day2-3: {step2}
• Day4-7: {step3}

😈 악마의 변호인
• 치명적 결함: {fatal_flaws}
• 시장 리스크: {market_risk}
• 실행 리스크: {execution_risk}
• 유사 실패: {similar_failures}

📊 종합 판정: {verdict}
```

Vault 저장 경로: `vault/Research/Ideas/{DATE}-{title}.md`

## 6) 운영 규칙

### 전환 규칙
1. 아이디어는 반드시 버튼 승인을 거쳐야 실험실로 이동
2. 아이디어 실험실에서 카드 기반으로만 대화
3. 실험 종료 후 결과 요약을 운영 메인으로 역전송

### 보고 형식
- 운영 메인: 결정/근거/다음 액션 중심
- 아이디어 실험실: 가설/실험/KPI/회고 중심

### 금지 사항
- 같은 아이디어를 두 토픽에서 병렬 진행 금지
- 카드 없이 장문 브레인스토밍만 반복 금지

### SLA
- 버튼 승인 후 약 30분 내 3인 토론 완료 + 카드 생성
- 실험 결과는 24시간 내 운영 메인에 요약 전송

## 8) ⚡️ Fast Track 시스템 (2026-02-20 추가)

`type == "openclaw"` 아이디어는 내부 시스템 개선 제안이므로 시장성/사업성 평가 불필요.

### 단계 구성

| 단계 | 일반 아이디어 | openclaw (Fast Track) |
|------|-------------|----------------------|
| trend | ✅ trend-scout 분석 | ⏭ 자동 skipped |
| tech | ✅ ops-dev 분석 | ✅ ops-dev 분석 |
| biz | ✅ biz-writer 분석 | ⏭ 자동 skipped |
| critic | ✅ main 분석 | ✅ main 분석 |

### 판정 기준
- 일반: 3개 분야 투표 기준 → `추천` 3개면 강력 추천
- openclaw: tech 1개 기준 → tech 판정만으로 결정

### 최종 카드 버튼 (openclaw)
| 버튼 | 콜백 |
|------|------|
| 🗑 패스 | `idea:pass:ID` |
| 🔍 레퍼런스 조사 더 하기 | `idea:deepfast:ID` |
| 🛠 적용 하기 (코딩 착수) | `idea:code:ID` |

## 9) 🔍 심층 조사 모드 분기 (2026-02-20 추가)

`idea:deep:ID` 버튼 클릭 시 아이디어 타입에 따라 분기:

### openclaw → 모드 선택 메시지 전송
아이디어 실험실 토픽에 인라인 버튼 메시지가 나타남:
- **[🔍 레퍼런스만 조사]** → `idea:deepfast:ID` → Fast Track 유지 (tech+critic 2단계)
  - ops-dev: GitHub/npm/블로그 기술 문서 조사
  - trend-scout: bird(트위터) + youtube-watcher(유튜브) 병렬 조사
- **[📊 풀 4단계 재분석]** → `idea:deepfull:ID` → 완전 재분석 (외부 수익화 검토 시)

### 일반 아이디어 → 바로 풀 4단계 deep-init
버튼 없이 즉시 4단계 라운드 2 시작

## 10) 🤖 자동화 오케스트레이터 (2026-02-20 추가)

`idea-lab-loop` 크론: **매 1시간마다** 자동 실행

동작 방식:
1. `process_idea.js --list` → discussing 아이디어 확인
2. discussing 없으면 조용히 종료
3. discussing 있으면 세션 status 확인 → 미완료 phase 파악
4. **openclaw → trend/biz spawn 금지, tech+critic만 spawn**
5. **일반 → 4단계 전부 순차 spawn**
6. allDone: true → `--finalize` 자동 실행

결과: 승인 버튼 한 번 누르면 **최대 1시간 내 완전 자동 토론 + 카드 생성**.
