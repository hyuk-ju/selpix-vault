# 브랜치 운영 표준 (Selpix 팀)

## 목적
운영 본선(`main`) 안정성을 유지하면서, 실험/수정/리팩토링 작업을 안전하게 수행하기 위한 표준 절차.

## 적용 범위
- `config` 레포: `/home/dev/openclaw/config`
- `vault` 레포: `/home/dev/openclaw/config/workspace/vault`
- `workspace` 레포는 자동 생성 파일이 많아 **기본적으로 브랜치 실험 대상에서 제외** (필요 파일만 선택 적용)

## 브랜치 네이밍 규칙
- 기능: `feature/<짧은설명>-YYYYMMDD`
- 운영수정: `ops/<짧은설명>-YYYYMMDD`
- 핫픽스: `hotfix/<짧은설명>-YYYYMMDD`
- 문서: `docs/<짧은설명>-YYYYMMDD`

예시:
- `ops/cron-timeout-fix-20260222`
- `feature/qa-handler-20260222`

## 기본 작업 플로우
1. 현재 상태 점검
   - `git status -sb`
2. 브랜치 생성/전환
   - `git checkout -b ops/<name>-YYYYMMDD`
3. 변경 적용 (범위 최소화)
4. 검증 실행
   - dry-run / 테스트 / 로그 확인
5. 커밋
   - `git add -A && git commit -m "<요약>"`
6. 최종 검토
   - `tester` PASS/FAIL 확인 (필수)
7. 본선 반영
   - `main` 병합 후 브랜치 삭제

## 충돌 포인트와 회피 규칙

### 1) 자동화 크론이 파일을 계속 갱신
- 증상: 브랜치 작업 중 워킹트리가 계속 dirty
- 회피:
  - 운영 변경은 `config` 레포에서 우선 수행
  - `workspace`는 로그/메모/자동산출물 제외하고 최소 파일만 수정

### 2) 같은 파일 동시 수정 (`cron/jobs.json`, `openclaw.json`)
- 증상: merge 충돌, 설정 누락
- 회피:
  - 브랜치당 변경 목적 1개 원칙
  - 병합 전 `git diff main...<branch>`로 범위 확인

### 3) 문서와 코드 변경이 한 커밋에 섞임
- 증상: 롤백/감사 어려움
- 회피:
  - 코드 커밋과 문서 커밋 분리
  - Vault 기록은 별도 커밋

## Ralph Loop와의 호환성

### 결론
- **기본적으로 충돌 없음**.

### 근거
- Ralph Loop 대상 경로는 `/home/dev/openclaw/selpix` 중심으로 운영됨.
- 본 브랜치 표준은 `config`, `vault`, `workspace` 운영 레포 기준.
- 경로/역할이 분리되어 동시 운영 가능.

### 충돌이 생길 수 있는 경우
- Ralph Loop가 `config/openclaw.json`, `config/cron/jobs.json` 같은 운영 설정까지 동시에 수정할 때

### 충돌 방지 가드
1. Ralph Loop 1회차에는 작업 1건만 수행
2. 운영 설정 파일 수정 시 브랜치명에 `ops/` 강제
3. 병합 전 `tester` PASS 확인
4. 결과를 `vault/Memory/변경로그.md`에 기록
