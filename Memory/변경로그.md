### 2026-03-02 19:40 KST — 쿠팡 크론 오류 2종 근본 수정 (stock_monitor + register_product)
- **변경**:
  - `cron_stock_monitor.js`: `stopCoupangSellerProductSale()` 함수에서 존재하지 않는 쿠팡 API 엔드포인트(`/seller-products/sales/stop/{id}`) 호출 제거. 매번 실패 후 fallback(`vendor-items` 개별 중지)으로 성공하던 구조 → fallback인 `stopCoupangSale()` 직접 호출로 단순화. 불필요한 API 호출 1회 + 에러 로그 55건/실행 완전 제거.
  - `cron_register_product.js`: 3가지 변경 —
    1. **`pickBestAllowedValue()` 신규 함수**: 쿠팡 카테고리 속성 허용값(allowedValues) 불일치 시 자동 보정 시도. 5단계 매칭: (1) 대소문자/공백 무시 정확 매칭, (2) 부분 문자열 매칭, (3) 수량 타입 숫자 근사 매칭, (4) 색상 타입 혼합→기타 매칭, (5) 사이즈 타입 FREE→프리/F 매칭
    2. **`sanitizeAttributeByMeta()` 허용값 보정 로직 삽입** (기존 line 94~97): `allowedValues`에 값이 없으면 즉시 skip → `pickBestAllowedValue()`로 대체값 시도 후 실패 시에만 skip
    3. **skip_invalid 재시도 로직** (기존 line 839~846): 쿠팡 API가 "유효하지 않은 구매 옵션 값 혹은 단위"로 거절 시 즉시 `skip_invalid` 영구 마킹 → `attrRetryCount` 기반 최대 2회 재시도. 재시도 시 `attributes`, `coupangPayload` 초기화 후 `pending`으로 복원 → 다음 배치에서 카테고리 재추정 + 속성 재생성. 2회 실패 시 `SKIP_FINAL`로 영구 마킹
  - `register_queue.json`: 기존 `skip_invalid` 33건을 `attrRetryCount=1`, `status=pending`으로 일괄 복원 (jq 1회성 스크립트). 자동 보정 + 재시도 기회 1회 부여
- **사유**: 크론 실행마다 두 종류 에러가 반복 발생 — (1) stock_monitor에서 미지원 엔드포인트 호출 실패 55건/실행이 에러 집계에 잡힘, (2) register_product에서 속성값-카테고리 허용값 불일치로 8/10건 등록 실패 → skip_invalid 영구 마킹 후 7일 뒤 삭제되어 상품 손실
- **영향**:
  - stock_monitor: 에러 55건/실행 → 0건. 불필요한 API 호출 제거로 실행 시간 단축
  - register_product: 속성 불일치 시 자동 보정으로 등록 성공률 향상. 실패해도 2회 재시도 후 최종 스킵하여 일시적 API 오류 복구 가능. 기존 skip_invalid 33건 중 재시도 가능 건 복원
  - 검증 결과: stock_monitor "No exactly" 에러 0건 확인, register_product 문법 검증 통과 + RETRY_QUEUED 정상 동작 확인
- **롤백**:
  - stock_monitor: `stopCoupangSellerProductSale()` 함수 내 원래 PUT 호출 + fallback 구조 복원
  - register_product: `pickBestAllowedValue()` 함수 삭제, `sanitizeAttributeByMeta()` line 94~97 원복 (`return { ok: false }`), skip_invalid 재시도 로직 제거 (즉시 `skip_invalid` 마킹으로 복원)
