## Phase 1: 즉시 적용 (프롬프트/설정 변경만)

### 1-A. Karpathy 4원칙 → SOUL.md 반영

- **소스**: forrestchang/andrej-karpathy-skills (8.1k stars)
- **대상**: `SOUL.md` §2 Voice & Tone 다음에 새 섹션 추가
- **가이드북 근거**: 23장 "스킬이 가장 먼저 붙는다" — 자주 쓰는 절차를 규칙 파일로 고정

**추가 내용**:
```markdown
## 🧠 실행 원칙 (Karpathy 4원칙 — 모든 에이전트 공통)

1. **Think Before Acting** — 실행 전 가정 3개를 명시한다. 모호하면 실행 대신 질문.
2. **Simplicity First** — 최소 코드, 과잉설계 금지. "절반 길이로 가능한가?" 자문.
3. **Surgical Changes** — 요청된 부분만 수정. 인접 코드 "개선" 금지.
4. **Goal-Driven** — 모호한 요청 → 측정 가능한 성공 기준 3개로 변환 후 실행.
```

**삽입 위치**: §2 Voice & Tone과 §3 팀 구조 사이
**리스크**: 낮음. 프롬프트 추가만. 토큰 ~50개 증가.
**검증**: 에이전트가 "📍 직접실행" 전에 가정 명시하는지 1주일 관찰

**선별 적용 항목**:

|------------|--------------|----------|

| 4 에이전트 (architect/reviewer/researcher/operator) | OpenClaw 8 에이전트 | 해당 없음 (서버 에이전트 별도) |
| 5 capability packs | 직무별 스킬 묶음 | Research + DevOps 팩 참고 |

**핵심 액션**: Claude Code settings.json에 hooks 설정
```json

    "PreToolUse": [{ "matcher": "Bash", "command": "echo 'Think before acting'" }],
    "PostToolUse": [{ "matcher": "Write", "command": "echo 'Verify output'" }]
  }
}
```

### 2-B. 크론잡 정리 — 가이드북 23장 참고

- **가이드북 핵심**: "먼저 스킬로 반복 절차를 고정 → cron으로 시각 실행 → 하트비트로 상태 확인"
- **현재 문제**: 62개 크론잡 중 inbox-handler 6개가 2~3분 간격 → 토큰 대량 소비
- **Zigrix 참고**: dispatch → evidence → finalize 패턴

**정리 후보**:

| 카테고리 | 현재 | 제안 |
|---------|------|------|
| inbox-handler (6개) | 2~3분 간격 각각 실행 | 통합 1개로 합치고 5분 간격 |
| self-healing (3개) | 10~23분 간격 | 2개로 통합, 15분 간격 |
| digest (3개, 1 OFF) | morning/afternoon/evening | 유지 (적절) |
| team-dispatch | 15분 간격 | 유지 (핵심 오케스트레이션) |

**기대효과**: 일 토큰 소비 20~30% 감소 추정
**리스크**: 높음. 크론잡 변경은 에이전트 응답성에 직접 영향.

### 2-C. 가이드북 부록B 모델 정책 반영

- **가이드북 핵심**: "강한 모델은 판단에, 가벼운 모델은 점검에"
- **현재**: 대부분 gpt-5.4 사용 (8% 세션 토큰)
- **제안**: auditor/tester 크론은 gpt-5.3-codex-spark로 분리 (비용 절감)
- **리스크**: 중간. 모델 분리 시 품질 저하 가능성.
