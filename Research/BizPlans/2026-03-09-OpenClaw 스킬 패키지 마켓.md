# 사업계획서: OpenClaw 스킬 패키지 마켓

> 운영팀/창업자 + 에이전트가 맥락 없이 헛도는 문제 + 스킬 폴더 기반 업무별 실행팩 배포

## 1. 시장 분석

| 항목 | 내용 |

| SAM (접근 가능) | 초기 접근 가능 시장은 북미/영어권 중심 AI agent 구축·자동화 도입 기업군으로 추정. Grand View 기준 북미 비중 39.63%를 적용하면 2025년 북미 AI agents 시장은 약 USD 3.0B 수준이며, 이 중 템플릿/패키지/설치·운영 레이어 20~35%를 실질 SAM으로 보면 약 USD 0.6B~1.1B. |

### 주요 트렌드
1. ready-to-deploy agents 비중이 2024년 58.7%로 크고, build-your-own agents도 고성장 중이라 패키지형 배포 레이어 수요가 커지고 있음
2. PwC 2025 조사에서 도입 기업의 66%가 생산성 개선을 보고해 '에이전트 실험 → 운영화' 전환 수요가 커지고 있음
3. low-code/visual builder 확산으로 비개발자 운영팀도 자동화 자산을 재사용 가능한 패키지로 소비하려는 흐름이 강화되고 있음

## 3. 타겟 고객

- **페르소나:** OpenClaw/에이전트 자동화 도구를 이미 만지거나 곧 도입하려는 1인 SaaS 창업자, 운영 자동화 컨설턴트, 소규모 Ops 팀 리드
- **핵심 문제:**
  1. 프롬프트·워크플로우·설정 파일이 흩어져 있어 재사용 가능한 운영 자산으로 묶이지 않음
  2. 에이전트 도입 후에도 설치/버전 충돌/권한 문제 때문에 실서비스 적용 속도가 느림
  3. 반복 업무용 플레이북을 팀에 배포할 때 문서화와 온보딩 비용이 지나치게 큼
- **지불 의향:** 개인/소규모 팀은 월 USD 29~129 구독 + 필요 시 USD 300~800 온보딩/튜닝 비용 지불 가능성이 높음. 다만 초기에는 '설치 성공률'과 '바로 쓰는 패키지 수'가 가격 저항을 좌우함

## 4. 제품 전략

- **핵심 가치:** OpenClaw용 스킬·플레이북·설정 묶음을 업무 단위 패키지로 배포하고, 호환성 검사·설치·업데이트·롤백까지 표준화해 '에이전트 실험'을 '반복 가능한 운영 자산'으로 바꾼다.
- **차별화:** 범용 자동화 빌더가 아니라 'OpenClaw 실무 패키지 유통 + 설치 검증 + 운영 재사용'에 집중한다. 즉, 템플릿 판매가 아니라 버전/권한/의존성까지 묶은 실행형 업무 패키지라는 점이 차별점이다.
- **기술 스택:** Node.js 22 + TypeScript API, PostgreSQL(JSONB) + Redis 큐, Docker Compose 배포, OpenClaw workspace adapter, Stripe 결제, static catalog UI(Next.js 또는 Astro), object storage(S3 호환)로 패키지 아카이브 저장
- **MVP 기능:**
  1. 패키지 카탈로그(카테고리/태그/호환 버전/권한 요구사항 표기)
  2. 패키지 메타데이터 스키마 및 검증기
  3. 설치/업데이트/롤백 CLI
  4. OpenClaw 버전 호환성 검사
  5. 샘플 패키지 3~5종(고객지원/리서치/운영자동화)
  6. 설치 성공률/실패 원인 관측 대시보드
  7. 결제 후 다운로드·라이선스 토큰 발급

## 5. 수익 모델

- **모델:** 구독형 허브 + 단품 패키지 판매 + 온보딩/튜닝 서비스 + 향후 서드파티 판매 수수료
- **단위 경제:** 목표 총마진 65~75%. 핵심은 지원시간을 계정당 월 25분 이하로 유지하는 것. 템플릿 판매보다 설치 성공률·롤백 안정성 향상이 CAC 회수와 유지율을 좌우한다.
- **손익분기:** 월 고정비 USD 20k~30k 가정 시, Pro 환산 180~250 seats 또는 Setup 포함 혼합 매출로 월 USD 25k~35k 달성 시 손익분기 가능

## 6. 실행 로드맵

### 1주차
- [ ] 패키지 메타데이터 스키마 정의(name, version, compatibility, permissions, hooks)
- [ ] 고객지원/리서치/운영자동화 3개 샘플 패키지 선정
- [ ] 호환성 검사기와 설치 CLI UX 설계
- [ ] 랜딩페이지와 대기명단 폼 공개

### 2-4주차
- [ ] 카탈로그 API, 패키지 레지스트리, 다운로드/라이선스 토큰 발급 구현
- [ ] 설치/업데이트/롤백 CLI 및 로그 수집 완성
- [ ] 파일럿 고객 5~10곳에 무료/할인 배포 후 설치 성공률 측정
- [ ] 지원 티켓 분류 체계와 실패 코드 표준화

### 2-3개월
- [ ] 유료 플랜 전환, 결제 연동, 팀 공유 기능 출시
- [ ] 서드파티 패키지 제출/검수 파이프라인 베타 오픈
- [ ] 관측 대시보드와 유지율/성공률 KPI 자동 리포트 추가
- [ ] 1개 산업군(예: 고객지원 자동화) 특화 패키지 번들 확장

### 마일스톤
1. M1: 설치 성공률 90% 이상
2. M2: 첫 10개 유료 계정 확보
3. M3: 지원 티켓 중 설치/호환성 이슈 비중 35% 이하
4. M4: 월 반복매출 USD 10k 달성 후 마켓/서드파티 검수 베타
