## 2. 즉시 실행 가능 (확인 후)

### 2-1. netdata 제거 → ~366 MB 절약

**현상**: netdata가 Docker 컨테이너 + 호스트 플러그인으로 366 MB 차지

**근거**:
- 시스템 모니터링은 이미 3중으로 존재:
  - `system_auditor.js` — 4시간마다 시스템 점검 (CPU, 메모리, 디스크, 프로세스)
  - `uptime-kuma` — 서비스 업타임 감시
  - `Langfuse` — LLM 사용량 모니터링
- netdata는 실시간 대시보드 제공하나, **현재 아무도 안 보고 있음**
- `system_auditor.js`가 이미 CPU/메모리/디스크 임계값 감지 + 텔레그램 알림

**실행**:
```bash
cd /home/dev && docker compose -f docker-compose.netdata.yml down
# 또는 netdata compose 파일 위치에 따라
docker stop netdata && docker rm netdata
```

**롤백**: `docker compose -f docker-compose.netdata.yml up -d`

### 2-2. Langfuse 판단 — 유지 vs 제거 → ~1,357 MB 절약 가능

**현황**:
- trace 3,578건 축적
- `metrics_collector.js` (매시간) + `weekly_cost_report.js` (주간)이 API 호출
- ClickHouse 단독 492 MB — 전체 Docker 최대 소비자

**유지 시 이득**:
- LLM API 사용량/비용 추적
- 크론잡별 토큰 소비 분석
- 주간 비용 리포트 자동 생성

**제거 시 이득**:
- 1.3 GB 메모리 즉시 확보
- Swap 3.9 GB → ~2.5 GB로 감소 예상

**제안**: 사용자 판단 필요. 대안으로 Langfuse 메모리 제한 설정 가능:
```yaml
# docker-compose.langfuse.yml
services:
  clickhouse:
    deploy:
      resources:
        limits:
          memory: 300M   # 현재 492MB → 300MB 제한
  web:
    deploy:
      resources:
        limits:
          memory: 256M   # 현재 376MB → 256MB 제한
  worker:
    deploy:
      resources:
        limits:
          memory: 128M   # 현재 189MB → 128MB 제한
```

이렇게 하면 제거 없이 ~1,357 MB → ~750 MB (약 600 MB 절약)

### 2-3. uptime-kuma 판단 — 유지 vs 제거 → 87 MB 절약 가능

**현황**: 서비스 업타임 모니터. 대시보드 웹 UI 제공.

**대체 가능**:
- `system_auditor.js`가 이미 프로세스 상태 확인
- `self_healing_monitor.js`가 크론잡 장애 감지

**제안**: 외부에서 접근해서 보는 용도가 아니면 제거 가능. 87 MB 작지만 기여.
