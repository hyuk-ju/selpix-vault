# AI 아키텍처 & LLM 학습 로드맵

> 비개발자가 AI 시스템 설계자로 성장하기 위한 단계별 학습 경로

## 현재 레벨 진단

| 영역 | 현재 수준 | 목표 |
|------|----------|------|
| LLM 구조 | 토큰/컨텍스트 윈도우 개념 파악 | Transformer 작동원리, 모델 선택 기준 |
| 에이전트 아키텍처 | 개념 이해 (직접 구축 경험 없음) | 멀티에이전트 시스템 설계/디버깅 |
| 프롬프트 엔지니어링 | AI 사용 가능 수준 | 시스템 프롬프트 설계, 에이전트 행동 제어 |
| 데이터 리터러시 | 기초 | 에이전트 성능 측정, 비즈니스 데이터 분석 |
| 코딩 | AI가 짠 코드 실행 수준 | AI에게 정확한 지시를 내릴 수 있는 수준 |

## Phase 1: LLM 구조 이해 (2~3주)

> 목표: "왜 AI가 이렇게 동작하는지" 직관적으로 이해하기

### 핵심 개념

- Transformer 아키텍처 (Attention, Self-Attention)
- 토큰화와 비용 구조 (왜 한국어가 영어보다 비싼지)
- 컨텍스트 윈도우와 메모리 한계
- Temperature, Top-p (출력 다양성 제어)
- 임베딩과 벡터 (RAG의 기초)
- 파인튜닝 vs 프롬프트 엔지니어링 차이

### 체크포인트 (스스로 확인)

- [ ] "토큰이 뭐야?" → 글자가 아니라 단어 조각이고, 한국어는 영어보다 토큰이 많이 든다
- [ ] "컨텍스트 윈도우가 뭐야?" → AI가 한 번에 볼 수 있는 텍스트 양의 한계
- [ ] "Temperature 높이면 뭐가 달라져?" → 답변이 더 창의적/랜덤해진다
- [ ] "RAG가 뭐야?" → 외부 문서를 검색해서 AI에게 먹여주는 방식
- [ ] "파인튜닝은 언제 써?" → 프롬프트만으로 안 될 때, 모델 자체를 재훈련

## Phase 2: 에이전트 아키텍처 설계 (3~4주)

> 목표: 에이전트 시스템의 설계 패턴을 이해하고, OpenClaw 시스템을 구조적으로 분석/개선할 수 있게 되기

### 핵심 개념

- Agent vs Workflow 차이 (동적 판단 vs 고정 흐름)
- ReAct 패턴 (Reasoning + Acting 루프)
- Tool Use / Function Calling (에이전트가 도구를 사용하는 방식)
- 라우팅과 오케스트레이션 (어떤 에이전트에게 보낼지 결정)
- 메모리 아키텍처 (단기/장기/작업 메모리)
- 에이전트 평가 (어떻게 잘 하고 있는지 측정)
- MCP (Model Context Protocol) — AI가 외부 시스템과 연결되는 표준

### 학습 리소스

#### 핵심 문서 (반드시 읽기)

   - 단순→복잡 순서로 패턴 설명 (Prompt Chaining → Routing → Orchestrator-Workers)

2. **[필수] Anthropic - Effective Harnesses for Long-Running Agents**
   - https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents

3. **Google Cloud - MCP 가이드**
   - https://cloud.google.com/discover/what-is-model-context-protocol
   - MCP가 뭔지, 왜 중요한지 개요

#### 강의/코스

4. **[추천] Hugging Face - AI Agents Course (무료, 수료증)**

   - 비개발자도 수강 가능, 수료증 발급

### 실습 제안

- OpenClaw의 현재 아키텍처를 Anthropic 가이드의 패턴으로 분류해보기
  - "장/탐/달 구조는 Orchestrator-Workers 패턴인가?"
  - "라우팅 게이트(ADR-027)는 어떤 패턴에 해당하나?"
- 각 에이전트의 시스템 프롬프트를 분석하고 개선점 찾기

### 체크포인트

- [ ] "Agent와 Workflow의 차이가 뭐야?" → Agent는 스스로 판단, Workflow는 미리 정해진 순서
- [ ] "ReAct 패턴이 뭐야?" → 생각하고(Reason) → 행동하고(Act) → 결과를 관찰(Observe)하는 루프
- [ ] "Tool Use가 뭐야?" → AI가 검색, API 호출 등 외부 도구를 사용하는 것
- [ ] "MCP가 뭐야?" → AI가 외부 시스템(파일, DB, API 등)과 표준화된 방식으로 연결하는 프로토콜
- [ ] OpenClaw를 Anthropic 패턴으로 설명할 수 있다

## Phase 3: 프롬프트 엔지니어링 심화 (2~3주 + 지속)

> 목표: 에이전트의 행동을 정밀하게 제어하는 시스템 프롬프트를 설계할 수 있게 되기

### 핵심 기술

- 시스템 프롬프트 설계 (역할, 제약, 출력 형식 정의)
- Few-shot prompting (예시를 줘서 패턴 학습)
- Chain-of-Thought (단계별 사고 유도)
- 구조화된 출력 제어 (JSON, XML, Markdown 등)
- 프롬프트 디버깅 (왜 원하는 답이 안 나오는지 추적)
- 프롬프트 체이닝 (여러 프롬프트를 연결하는 워크플로우)

### 학습 리소스

   - 공식 한국어 문서, 가장 체계적

2. **[필수] Anthropic Interactive Prompt Engineering Tutorial**
   - https://github.com/anthropics/prompt-eng-interactive-tutorial
   - Jupyter 노트북 기반 실습 (AI한테 시켜서 실행 가능)

3. **Anthropic Prompt Engineering 완벽 가이드 (한국어 블로그)**
   - https://velog.io/@euisuk-chung/Anthropic-Prompt-Engineering-완벽-가이드
   - Anthropic 공식 내용을 한국어로 정리

4. **Claude 4 프롬프트 엔지니어링 모범 사례 (한국어)**
   - https://docs.anthropic.com/ko/docs/build-with-claude/prompt-engineering/claude-4-best-practices

### 실습 제안

- OpenClaw 에이전트별 시스템 프롬프트를 분석하고 리팩토링
- 같은 작업에 대해 프롬프트를 3가지 방식으로 작성하고 결과 비교
- 프롬프트 라이브러리를 Vault에 구축 (Templates/ 활용)

### 체크포인트

- [ ] 시스템 프롬프트에 역할/제약/출력형식을 구분해서 작성할 수 있다
- [ ] Few-shot 예시를 3~5개 넣어서 패턴을 가르칠 수 있다
- [ ] "AI가 이상한 답을 했을 때" 프롬프트의 어디가 문제인지 추적할 수 있다
- [ ] JSON/구조화된 출력을 안정적으로 뽑아낼 수 있다

## 학습 원칙

1. **영상 먼저, 문서로 복습** — 영상으로 직관 잡고, 문서로 정확한 용어를 익힌다
2. **배운 건 바로 OpenClaw에 적용** — 이론만 쌓지 말고, 실제 시스템에 반영
3. **Vault에 학습 노트 남기기** — Research/ 폴더에 TIL(Today I Learned) 기록
4. **한 번에 한 Phase만** — 동시에 여러 개 하면 어느 것도 안 끝남
5. **모르면 AI에게 물어보기** — "이 개념을 초등학생한테 설명하듯이 알려줘"
