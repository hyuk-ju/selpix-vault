## Run 1: 0/100 — CLI 기본 오류

### 증상
- 26개 테스트 **전부** `"Pass --to <E.164>"` 에러로 실패
- 에이전트가 아예 호출되지 않음

### 원인 1: `--agent main` 플래그 누락
- 초기 코드: `openclaw agent -m "메시지" --json`
- `--agent` 미지정 시 OpenClaw은 Telegram 메시지 전송 모드로 진입 → E.164 전화번호 요구
- **수정**: `openclaw agent --agent main -m "메시지" --json`

### 원인 2: `.env` 파일 로드 실패
- `require('dotenv').config()` 대신 직접 regex 파싱 사용
- 초기 regex: `/^([A-Z_]+)=["']?(.*?)["']?\s*$/`
- **버그**: `OPENAI_API_KEY` 같은 숫자 포함 변수명 매칭 실패 (`[A-Z_]+`는 숫자 불포함)
- **수정**: `/^([A-Z_][A-Z0-9_]*)=["']?(.*?)["']?\s*$/`

### 원인 3: `.env` shell source 불가
- `.env`에 한국어 주소(`# 주소: 서울시...`)와 특수문자(`(`, `)`) 포함
- `source /home/dev/openclaw/.env` → bash 파싱 에러
- **결론**: Node.js regex 파서 필수, bash source 절대 금지

## Run 2: 29/100 — 가짜 응답으로 채점

### 증상
- 26개 테스트 전부 "성공"으로 처리되었으나, 점수가 비정상적으로 낮음
- Judge가 채점한 "응답"이 실제 에이전트 답변이 아니라 JSON 메타데이터

### 원인: `payloads` 필드 미발견
- `openclaw agent --json` 출력 구조:
  ```json
  {
    "status": "ok",
    "result": {
      "meta": { "aborted": true/false, "durationMs": ..., "agentMeta": {...} },
      "payloads": [{ "text": "실제 응답" }]
    }
  }
  ```
- 코드가 `result.meta`만 파싱하고 `result.payloads`를 무시
- `meta` 객체를 문자열화한 것을 "에이전트 응답"으로 Judge에 전달
- Judge는 `{"sessionId":"b5c37d9e","aborted":true,...}` 같은 JSON 문자열을 채점 → 당연히 저점

### 부가 발견
- `aborted: true`인 경우가 다수 — 에이전트가 120초 타임아웃 내에 응답 완료 못함
- 에이전트 실제 응답은 Telegram으로만 전송되고 stdout에는 포함 안 됨 (이것이 착각의 원인)
- **실제로는** `payloads[0].text`에 응답이 있었으나, `aborted: true`일 때는 `payloads: []`

## 핵심 기술 교훈

### 1. `payloads[0].text`가 정답
- `openclaw agent --json`의 `result.payloads[0].text`에 에이전트 최종 응답이 있음
- 세션 로그(`.jsonl`) 파싱은 불필요하고 불안정 (멀티턴에서 마지막 assistant 메시지 특정 어려움)

### 2. 세션 컴팩션은 시간이 걸린다
- 198K 토큰 세션 → 컴팩션에 175초+
- `--timeout 120`(기본)으로는 부족, `--timeout 300` 필요
- 컴팩션 한번 완료되면 이후 호출은 22초대로 안정

### 3. 새 세션 강제 불가
- `--session-id`로 새 UUID 지정해도 gateway가 agent별 고정 세션으로 라우팅
- `--local` 플래그도 동일 세션 사용
- 아키텍처 결정: 에이전트 1개 = 세션 1개

### 4. `.env` 파일은 Node.js로 파싱
- bash `source` 불가 (한국어, 특수문자)
- dotenv 라이브러리 또는 regex 파서 사용
- regex에서 변수명 패턴 `[A-Z_][A-Z0-9_]*` 주의

### 5. CLI 테스트의 한계
- `openclaw agent -m` = 항상 개인 채팅 컨텍스트
- 토픽별 systemPrompt 적용 안 됨
- 실제 Telegram 그룹 토픽 테스트는 Bot API 직접 호출 필요

### 6. Judge(LLM-as-Judge) 한계
- "위임했는가"만 보면 위임 의도만으로 고득점
- 결과 전달 여부, 도구 실행 여부 기준 필수
- Judge에 vault 데이터 스냅샷 없으면 사실 검증 불가
