# Obsidian 정리 자동화 (biz-writer 확장)

> 신규 에이전트 대신 biz-writer에 일일 정리 크론을 붙여 Vault/Obsidian 정리를 자동화

## 배경
매일 21:30 KST obsidian-daily-cleanup 크론으로 Daily 링크체인/백링크 보정, 대시보드 날짜·핵심 링크 업데이트, 할일-보드 상태 정리. 보고는 리포트 토픽(29)에 요약 5줄+변경 파일 경로. 1주 파일럿 후 누락률/재작업률/정리시간 KPI로 유지 여부 판단.

## 기술 분석 (ops-dev)
- **실현 가능성:** 기존 biz-writer 에이전트 크론 구조 활용 가능. 매우 높음
- **MVP 범위:** 단순 파일 기반 링크 검사 및 날짜 업데이트 스크립트 작성
- **추가 개발:** 하루 (cron_obsidian_cleanup.js 신규 작성)
- **판정:** 보류 — 기술적 난이도가 극도로 낮으며 시스템 유지보수에 큰 도움을 줌


## 악마의 변호인 (main)
> 의도적으로 반대 근거를 찾아 검증한 결과

- **치명적 결함:** 기술적으로 불가능한 치명 결함은 없지만, 콘텐츠 훼손 방지 장치(백업·dry-run·변경량 가드)가 없으면 즉시 실패 확률이 높다.
- **시장 리스크:** 외부 시장 리스크는 낮으나 내부 사용자 신뢰를 잃는 순간 도입이 중단되는 신뢰 리스크가 핵심이다.
- **실행 리스크:** 파일 파싱 경계조건, 다국어/특수문자 링크, 동시성 처리, git 충돌 처리 미흡이 주요 실행 리스크다.
- **유사 실패 사례:** 문서 자동 포맷터·링크 정리 봇에서 과보정으로 링크 스팸/본문 훼손이 발생해 수동 복구로 전환한 사례가 흔하다.
- **판정:** 보류 — 효용은 높지만 핵심 가정 3개가 미검증이며 최고 RPN 15로 안전장치 없는 즉시 상용 적용은 위험하다. 파일 훼손 방지 가드 검증 후 제한 도입이 타당하다.
