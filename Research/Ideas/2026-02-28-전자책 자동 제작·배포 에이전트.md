# 전자책 자동 제작·배포 에이전트

> 개인 창업자·AI 강사(타깃: 콘텐츠 제작자) 대상 짧은 기획 문구로 전자책 제작 자동화

## 배경
Source: 메이커 에반: '누워서 딸깍 한번에 전자책 완성' 영상, Nick Saraev의 Build & Sell/CLAUDE CODE 교육 흐름.
구성: 자료조사-원고-디자인-검수-발행까지 API 기반 자동 루틴을 한 번에 설정, OpenClaw 워크플로우 또는 독립 UI로 추상화.
수익화: 생성형 에이전트 구독 + 완성본 상위 템플릿 판매(월 $19~).

## 시장은?
- **수요:** 메이커 에반·AI 코치류 콘텐츠에서 자료 조사-원고-디자인-발행의 통합 자동화 니즈가 반복 언급되며, 1인 창업자·강사의 제작시간 단축 요구는 지속적으로 관찰된다.
- **경쟁:** 일반 AI 글쓰기/디자인 템플릿, PDF 생성, LMS·마케팅 배포 연동 툴 등 대체재가 이미 많아 진입 장벽은 높다. 유사 기능을 제공하는 범용 툴이 즉시 전환 대안이 될 수 있어 가격 경쟁과 기능 모방 압력이 크다.
- **타이밍:** 현재 시점은 시장 과열기로 수요 창출이 가능한 구간이지만, 독립 제품으로서의 차별화 검증이 먼저 필요하다. 먼저 내부 파일럿으로 유료 전환율/초기 CS율을 검증한 뒤, 특화 ICP를 좁혀 단계적으로 확장하는 것이 안전하다.
- **판정:** 보류 — 콘텐츠 제작 자동화 수요는 존재하나, 콘텐츠 제작자용으로는 이미 유사 AI 글쓰기/템플릿/배포 툴이 포화되어 ‘원클릭’만으로 즉시 차별화되기 어렵다. 특히 전자책 품질·브랜딩 일관성·지원 부하를 확보하지 못하면 환불과 이탈 리스크가 커진다.


## 만들 수 있나?
- **실현 가능성:** 중상 (기술 요소는 성숙했으나, 자동 검수/저작권 체크/배포 채널 연동까지 포함 시 운영 난이도 상승)
- **핵심 범위:** 타깃을 1인 강사용 단일 시나리오로 제한해 주제 입력→목차/초안 생성→템플릿 기반 PDF 1종 출력→랜딩 링크 발행까지만 자동화하고, 실제 배포 업로드는 반자동 승인 단계로 둔다.
- **추가 개발:** 풀스택 1명 + LLM/프롬프트 엔지니어 0.5명 + QA 0.5명 기준 4~6주 MVP, 배포 채널 자동화·저작권/품질 가드레일 포함 상용화 안정화 2~4주 추가
- **판정:** 보류 — 핵심 기능은 기존 LLM·문서 렌더링·결제 API 조합으로 구현 가능하지만, ‘자동 제작+배포’ 전체를 원클릭으로 묶으면 품질 편차와 예외 처리 비용이 초기에 크게 증가한다. MVP는 생성·검수·배포 범위를 좁혀 단계 검증이 필요하다.

## 돈이 되나?
- **수익 모델:** 월 구독형(기본 $19~$29) + 프리미엄 템플릿/배포 자동화 애드온
- **예상 KPI:** 파일럿 30일 유료전환율, 전자책 1권당 제작 리드타임, 환불률
- **판정:** 보류 — 초기 고객 수요는 있으나 범용 AI 저작/디자인 툴 대비 차별화가 약하면 CAC 대비 회수 기간이 길어질 가능성이 크다. ICP를 좁힌 파일럿 매출 검증 전까지 보수적 접근이 필요하다.

## 왜 안 될까?
> 의도적으로 반대 근거를 찾아 검증한 결과

- **치명적 결함:** 범용 AI 글쓰기/디자인/배포 툴 대비 가치 제안이 약해 가격 압박 및 기능 모방이 쉬움,원클릭 자동화에서 품질/브랜딩 일관성 보장 실패가 누적되면 환불·이탈로 CS 비용이 급증,LLM·문서렌더링·결제·채널 연동 의존도가 높아 장애·요금 변동 시 서비스 신뢰도가 즉시 하락
- **시장 리스크:** 원클릭 자동화에서 품질/브랜딩 일관성 보장 실패가 누적되면 환불·이탈로 CS 비용이 급증
- **실행 리스크:** LLM·문서렌더링·결제·채널 연동 의존도가 높아 장애·요금 변동 시 서비스 신뢰도가 즉시 하락
- **유사 실패 사례:** 유사 실패 데이터 추가 수집 필요
- **판정:** 보류 — 경쟁이 이미 성숙한 시장에서 '원클릭 전자책 자동 제작·배포'는 차별화가 약하고, 품질 편차·검수 실패를 막기 위한 운영 비용이 초기 수익성보다 앞서 발생할 위험이 높다. 유료 전환율, 반품률, 배포/저작권 오류율이 낮아지지 않으면 파일럿 단계에서 비용이 이익을 잠식할 가능성이 크다.
