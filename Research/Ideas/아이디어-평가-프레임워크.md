# 아이디어 평가 프레임워크

> 4명의 AI 에이전트가 아이디어를 평가할 때 사용하는 구조화된 기준.
> 일반 LLM 지식이 아닌, 우리 비즈니스(도매꾹→쿠팡 위탁판매 + AI SaaS)에 맞춘 평가 체계.

---

## 왜 필요한가?

현재 문제:
- 에이전트에게 "시장 관점에서 분석해줘"만 던지면 → 뜬구름 잡는 분석이 나옴
- 구체적 점수, 기준, Kill Criteria 없이 "추천/보류/반대"만 내리면 → 판단 근거 불명확
- 우리 사업 맥락(위탁판매 마진 구조, 1인 운영, AI 에이전트 실행)을 모르면 → 엉뚱한 분석

해결:
- 각 에이전트에게 **채점표(Scorecard)**를 줌
- 숫자로 점수를 매기게 해서 비교 가능하게 만듦
- Kill Criteria(이거 안 되면 바로 폐기) 명시

## 에이전트별 평가 프레임워크

### 1. trend-scout (시장 분석가)

**사용 프레임워크: DVS (Demand Validation Score) + TLP + CIS**

#### DVS — 수요 검증 점수 (각 1~5점, 총 25점 만점)

| 기준 | 1점 (나쁨) | 3점 (보통) | 5점 (좋음) |
|------|-----------|-----------|-----------|
| **네이버 검색 트렌드** (12개월 YoY) | 20%+ 하락 | 변동 없음 (±5%) | 20%+ 성장 |
| **쿠팡 경쟁 상품 수** (공급 포화도) | 10,000개+ (포화) | 1,000~10,000개 | 1,000개 미만 (블루오션) |
| **타겟 고객 일치도** | 20% 미만 | 40~60% | 70%+ |
| **계절성 안정도** (12개월 변동폭) | 3배+ 급등/급락 | 중간 계절성 | 연중 안정 |
| **마진 가능성** (쿠팡 판매가 vs 도매꾹 원가) | 1.5배 미만 | 1.5~2.5배 | 2.5배 이상 |

**해석:**
- 20~25점: 강력 추천 — 바로 진입
- 14~19점: 탐색 가치 있음 — 추가 조사 필요
- 13점 이하: 패스

#### TLP — 트렌드 수명주기 위치

| 단계 | 신호 | 점수 | 행동 |
|------|------|------|------|
| **태동기** (0~6개월 상승) | DataLab 지수 <30, 월 50%+ 상승, 쿠팡 판매자 <50 | 5 | 선점 기회 |
| **성장기** (6~18개월) | 지수 30~70, 꾸준한 상승, 50~500 판매자 | 4 | 차별화로 진입 |
| **정점** (최고치) | 지수 >70, 정체, 500~2000+ 판매자 | 2 | 원가 우위 있을 때만 |
| **하락기** | 피크 대비 15%+ 하락, 판매자 이탈 | 1 | 진입 금지 |

#### CIS — 경쟁 강도 점수 (각 1~5점, 총 20점 만점, 낮을수록 좋음)

| 요소 | 1점 (경쟁 약함) | 3점 (보통) | 5점 (격전) |
|------|---------------|-----------|-----------|
| **카테고리 판매자 수** | 100개 미만 | 100~1,000 | 1,000+ |
| **상위 3 판매자 점유율** | 30% 미만 (분산) | 30~60% | 60%+ (독점) |
| **가격 바닥 근접도** (최저가 vs 내 원가) | 내 원가가 최저가의 60% 미만 | 60~85% | 85%+ (마진 없음) |
| **로켓배송 점유율** (1페이지 기준) | 30% 미만 | 30~70% | 70%+ (진입 장벽) |

**해석:**
- 4~8점: 저경쟁 — 유리한 진입
- 9~14점: 중경쟁 — 차별화 필요
- 15~20점: 고경쟁 — 구조적 우위 없으면 회피

### 2. ops-dev (기술 엔지니어)

**사용 프레임워크: ICE Score + MVP 복잡도 + Build vs Buy**

#### ICE Score (각 1~10점, 평균으로 계산)

| 요소 | 설명 | 점수 기준 |
|------|------|-----------|
| **Impact** (영향도) | 핵심 지표에 얼마나 영향? | 1~3: 소소한 개선. 4~6: 의미 있는 지표 향상 (10~30%). 7~10: 새 수익원 개척 |
| **Confidence** (확신도) | Impact/Ease 추정에 얼마나 확신? | 1~3: 추측. 4~6: 유사 사례 있음. 7~10: 프로토타입 검증됨 |
| **Ease** (구현 용이성) | 현재 스택으로 얼마나 쉽게? | 1~3: 새 기술 필요, 2주+. 4~6: 중간, 3~7일. 7~10: 1~2일, 기존 도구 활용 |

**ICE 점수 = (Impact + Confidence + Ease) / 3**

- 7.0+: 즉시 실행 (다음 스프린트)
- 5.0~6.9: 다음 사이클에 계획
- 5.0 미만: 백로그 또는 폐기

#### MVP 복잡도 점수 (각 1~3점, 총 15점 만점, 낮을수록 좋음)

| 차원 | 1 (단순) | 2 (보통) | 3 (복잡) |
|------|---------|---------|---------|
| **새 API/서비스 필요** | 0개 (기존 것만) | 1~2개 추가 | 3개+ 추가 |
| **데이터 모델 변경** | 없음 | 기존 JSON 필드 추가 | 새 저장소/스키마 필요 |
| **UI 필요 여부** | 없음 (스크립트/자동화) | 간단한 대시보드/폼 | 완전한 사용자 제품 |
| **에러 처리 복잡도** | 해피패스면 충분 | 3~5가지 실패 모드 | 다수 엣지케이스, 상태 머신 |
| **테스트 난이도** | 수동 확인 수분 | 테스트 데이터 셋업 필요 | 스테이징 환경 필요 |

**해석:**
- 5~7점: 1~3일이면 AI 에이전트로 배포 가능
- 8~10점: 1~2주 스프린트
- 11~15점: 단계별 접근 필요, 범위 축소 검토

#### Build vs Buy 판단 (가중 평균)

| 기준 | 가중치 | 1 (사라/기존 것 쓰기) | 5 (직접 만들기) |
|------|--------|---------------------|----------------|
| **전략적 차별화** | 3x | 범용 기능 (이메일 등) | 핵심 경쟁력 (가격 알고리즘 등) |
| **출시 시급성** | 2x | 이번 주 필요 | 1~2개월 여유 |
| **기존 솔루션 품질** | 2x | 완벽한 SaaS/API 존재 | 맞는 게 없거나 비쌈 |
| **유지보수 부담** | 1x | 벤더가 관리 | 영구적으로 직접 관리 |
| **통합 복잡도** | 2x | 드롭인 API/모듈 | 깊은 커스텀 통합 필요 |

점수 < 2.5: Buy. 2.5~3.5: 하이브리드. > 3.5: Build.

### 3. biz-writer (비즈니스 기획자)

**사용 프레임워크: 단위경제 계산기 + 손익분기 추정 + 린캔버스**

#### 위탁판매 단위경제 (Per-Product)

```
매출 단가:           쿠팡 판매가 (A)
- 도매꾹 원가:        (B)
- 쿠팡 수수료 (~12%): (C) = A × 0.12
- 배송비:             (D)
- 광고비 배분:        (E) = 월 광고비 / 판매 수량
- 반품 비용 배분:     (F) = 반품률 × (B + D)
────────────────────
단위 이익:           (G) = A - B - C - D - E - F
이익률:              (H) = G / A × 100%

기준:
- 이익률 40%+: 우수
- 이익률 25~40%: 적정
- 이익률 25% 미만: 위험
```

#### 카테고리 점수 (각 1~5점, 총 25점 만점)

| 지표 | 1점 (나쁨) | 3점 (보통) | 5점 (좋음) |
|------|-----------|-----------|-----------|
| **단위 이익률** | 25% 미만 | 25~40% | 40%+ |
| **평균 주문 단가** | 1만원 미만 | 1~3만원 | 3만원+ |
| **예상 반품률** | 10%+ | 5~10% | 5% 미만 |
| **재구매 가능성** | 1회성 | 가끔 | 소모품/정기 |
| **광고 의존도** | 광고 없이 판매 불가 | 적당히 필요 | 유기적 발견 위주 |

#### 손익분기 계산

```
위탁판매:
  손익분기 수량 = 월 고정비 / 단위 이익
  예: 350,000원(서버+API+도구) / 5,000원(단위 이익) = 월 70개

SaaS:
  손익분기 기간 = 총 개발비 / (MRR - 월 운영비)
  CAC 회수 기간 = CAC / (ARPU × 이익률)
  목표: 6개월 이내 회수
```

#### 린캔버스 (Solo + AI 버전, 7블록)

| 블록 | 질문 |
|------|------|
| **1. 문제** (상위 3개) | 이 아이디어가 해결하는 구체적 고통은? |
| **2. 고객 세그먼트** | 정확히 누구? (좁게 정의) |
| **3. 고유 가치 제안** | 왜 우리여야 하는가? 대안 대비 차별점은? |
| **4. 솔루션** (MVP 기능 최대 3개) | 최소 실행 범위는? |
| **5. 수익 구조** | 돈이 어떻게 들어오는가? (건당 수수료/구독/수익 분배) |
| **6. 비용 구조** | 고정비 + 변동비 = ? |
| **7. AI 에이전트 구성** | 어떤 에이전트가 무엇을 담당하는가? |

### 4. critic (악마의 변호인)

**사용 프레임워크: Pre-Mortem + 가정 맵핑 + FMEA-Lite**

#### Pre-Mortem 분석 (사전 부검)

> "6개월 후, 이 아이디어가 완전히 실패했다. 매출 0, 시간만 낭비. 왜?"

**반드시 10가지 실패 이유를 강제 생성:**
- 시장 이유 2개 (수요 없음, 경쟁에 밀림)
- 기술 이유 2개 (구현 불가, API 문제)
- 경제 이유 2개 (마진 부족, 비용 초과)
- 운영 이유 2개 (1인으로 감당 불가, 번아웃)
- 외부 이유 2개 (규제 변화, 플랫폼 정책)

각 이유에 **RPN (Risk Priority Number)** 계산:

| 실패 모드 | 발생 확률 (1~5) | 영향도 (1~5) | 탐지 어려움 (1~5) | RPN |
|-----------|---------------|------------|----------------|-----|
| (각 10개 작성) | | | | P×I×D |

**RPN 상위 3개 → Kill Criteria 검토:**
- "이 리스크가 해소 불가능하면 아이디어를 폐기해야 하는가?"

#### 가정 맵핑 (Assumption Mapping)

아이디어의 핵심 가정을 나열하고 2x2 매트릭스에 배치:

```
           높은 리스크 (틀리면 아이디어 죽음)
                   |
  검증됨 ──────────┼────────── 미검증
  (데이터 있음)     |          (순수 가정)
                   |
           낮은 리스크 (틀려도 조정 가능)
```

**우선 검증 대상**: 높은 리스크 + 미검증 = 이것부터 테스트

각 핵심 가정에 Kill Criteria 정의:
```
가정:        "이 카테고리에서 35%+ 마진 상품이 존재한다"
검증 방법:    "도매꾹 2시간 소싱으로 20개 이상 발견"
Kill 기준:   "2시간 소싱으로 20개 미만 → 카테고리 폐기"
검증 기한:    "Day 1"
```

#### FMEA-Lite (실패 모드 분석, 경량판)

우리 파이프라인의 각 단계에서 이 아이디어가 만들 수 있는 장애:

| 파이프라인 단계 | 실패 모드 | 사업 영향 | 심각도 (1~10) | 발생빈도 (1~10) | 탐지도 (1~10) | RPN | 대응 |
|---------------|----------|----------|-------------|---------------|-------------|-----|------|
| 소싱 | (이 아이디어로 인한 실패) | | | | | | |
| 이미지 처리 | | | | | | | |
| 쿠팡 등록 | | | | | | | |
| SEO 최적화 | | | | | | | |

**RPN > 80 = 반드시 대응 계획 필요**

## 자동 판정 기준

| 조건 | 판정 |
|------|------|
| DVS ≥ 20 AND ICE ≥ 7 AND 단위경제 ≥ 20 AND Kill Criteria 0건 | **강력 추천** |
| DVS ≥ 14 AND ICE ≥ 5 AND 단위경제 ≥ 14 | **추천** |
| 어느 하나라도: DVS < 10 OR ICE < 3 OR 단위경제 < 10 | **반대** |
| Kill Criteria 1건 이상 트리거 | **반대** (critic 반대와 동일 효과) |
| 나머지 | **보류** |

## Phase 2 (심층 검증) 추가 기준

Phase 2에서는 Phase 1 점수 + 사용자 피드백을 반영하여:
- 미검증 가정 중 최소 2개 실제 검증 결과 포함
- 경쟁사 실제 데이터 (쿠팡 검색 결과, 가격대) 포함
- 단위경제에 실제 도매꾹 가격 반영 (추정 아닌 실데이터)
