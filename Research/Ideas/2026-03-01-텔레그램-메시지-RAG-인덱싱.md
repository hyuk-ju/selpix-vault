# 텔레그램 메시지 RAG 인덱싱

> 사용자 제안: 텔레그램 수신/발신 메시지를 주기적으로 vault에 저장하여 ChromaDB RAG로 검색 가능하게 만들기.

---

## 문제

현재 텔레그램 메시지는 일회성으로 소비됨:
- 다이제스트는 전송 후 초기화 (`[]`로 덮어쓰기)
- 과거에 받은 보고, 알림, 대화 내용을 다시 찾을 방법이 없음
- 에이전트가 "지난주 품절 알림 몇 번 왔어?" 같은 질문에 답 불가

## 구상

### 저장 단계
1. 다이제스트 전송 시 `daily_digest.json`을 vault에 날짜별 마크다운으로 저장
   - 경로: `vault/Memory/Telegram/YYYY-MM-DD-digest.md`
2. Telegram 수신 메시지(사용자 → 봇)도 별도 로그로 저장
   - 경로: `vault/Memory/Telegram/YYYY-MM-DD-chat.md`

### RAG 단계
3. 기존 `vault-rag-incremental-index` 크론잡이 자동으로 ChromaDB에 인덱싱
   - `vault/Memory/Telegram/` 디렉토리도 인덱싱 대상에 포함됨 (이미 vault 하위)
4. vault-search 스킬로 검색 가능

### 필요 작업
- `digest_sender.md` 수정: 전송 전 vault에 markdown 사본 저장 추가
- 또는 새 크론잡: `telegram-message-archiver` (15분마다 메시지 수집 → vault 저장)
- vault 용량 관리: 90일 이상 오래된 파일 자동 아카이브

### 기대 효과
- "지난주 긴급 알림 내역 알려줘" → vault-search 검색으로 즉시 답변 가능
- 트렌드 분석: "최근 한 달 품절 감지 빈도" 등 시계열 분석
- 의사결정 기록: 과거 대화에서 결정한 내용 추적
