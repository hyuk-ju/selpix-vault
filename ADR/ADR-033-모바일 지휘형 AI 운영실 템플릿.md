# ADR-033: 모바일 지휘형 AI 운영실 템플릿

## 맥락
source[youtube:LiamOttley/_He58Zi8NQg, youtube:NickSaraev/sduaTkhIm_w, youtube:ByteByteGo/5kHpeVvO7cY]: 휴대폰(텔레그램)에서 운영 명령→에이전트 실행→API 이벤트 수집까지 한 화면으로 묶는 운영실 템플릿. Selpix에 주문/문의/재고/콘텐츠 태스크를 붙여 '모바일 1인 운영' 시나리오로 내재화하고, 외부에는 템플릿+세팅 대행(초기 세팅비+월 유지비)으로 판매.

## 결정
**⚠️ 조건부 추천 (리스크 주의)**
- 시장: 추천 — 수요 신호와 도입 타이밍이 모두 강하고, 템플릿 단품이 아니라 세팅 대행+월 유지비 구조로 설계하면 마진 방어가 가능하다. 초기에는 업종 1~2개에 집중해 KPI(응답시간, 처리자동화율, 운영시간 절감)를 증명하면 경쟁 과밀 리스크를 상당 부분 상쇄할 수 있다.
- 기술: 추천 — 문제-해결 적합성이 높고, 소규모 팀의 상시 대기 부담을 즉시 줄여주는 운영 효용이 명확합니다. 또한 템플릿+세팅 대행+월 유지비 모델로 제품화와 서비스 매출을 동시에 만들 수 있어 사업성도 충분합니다. 다만 외부 API 장애와 권한 오남용 리스크를 대비해 감사로그/롤백/승인 플로우를 MVP 단계부터 포함해야 합니다.
- 비즈니스: 추천 — 문제(상시 PC 근무 부담)와 솔루션(모바일 지휘+자동화)이 명확하게 맞물려 초기 유료 전환 가능성이 높습니다. 템플릿+세팅 대행은 소규모 팀이 즉시 성과를 체감하기 쉬워 단가와 마진을 동시에 확보하기 좋습니다. 다만 초기 1주 파일럿에서 장애율과 유지율을 검증해 서비스 표준화 수준을 먼저 고정해야 합니다.
- 반대 검증: 반대 — 핵심 가치는 매력적이지만 외부 플랫폼 의존성과 운영 예외 처리 비용이 결합되면 템플릿형 상품의 반복가능성이 급격히 떨어진다. Pre-mortem 상위 RPN이 높고(최고 20), kill criteria가 초기 파일럿 단계에서 쉽게 트리거될 구조다. 현재 가정 검증 전에는 확장형 상품으로 추진하기보다 범위를 축소한 대안 실험이 우선이다.

## 검토한 대안
완전한 모바일 운영실 대신 업종별 1개 페인포인트(예: 문의 triage) 수직 SaaS로 축소,텔레그램 단일 채널 대신 웹 대시보드+메신저 알림 이원화로 플랫폼 종속도 완화,세팅 대행 중심이 아니라 성공수수료/성과지표 연동형 운영 코파일럿으로 가격모델 전환

## 트레이드오프
- 실행 시: MVP 범위 확정: 주문/문의/재고/콘텐츠 4개 플로우,텔레그램 지휘 명령 세트(조회/승인/실행/알림) 정의,파일럿 고객 3개 업종 가설 수립(소형 쇼핑몰, 1인 콘텐츠, 공동구매) → Selpix 이벤트 스키마 표준화 및 실패 재시도 정책 적용,초기 온보딩 템플릿(2시간 내 설치) 제작,가격표 A/B: 79만원+월12만원 vs 129만원+월15만원 테스트 → 파일럿 3곳 실제 운영 데이터 수집(명령 빈도, 절감 시간, 오류율),케이스 스터디 1페이지 정리 후 세팅 대행 제안서 완성,주요 병목(인증, API 한도, 예외 처리) 보강 후 정식 판매 판단
- 미실행 시: 기회 비용 발생

## 리스크 및 탐지 신호
| 리스크 | 내용 | 탐지 신호 |
|--------|------|-----------|
| 치명적 결함 | 단일 메시징 채널(텔레그램)과 외부 API에 과의존한 구조로 플랫폼 리스크가 즉시 사업 리스크로 전이됨,템플릿 상품인데도 고객별 운영 예외 처리가 많아 서비스가 사실상 고비용 SI로 변질될 가능성,자동화 오류의 책임소재/보상체계가 불명확하면 초기에 신뢰를 잃고 레퍼런스 확장 실패 | 초기 검증 실패 |
| 시장 리스크 | 중간~높음: 문제(상시근무 피로)는 명확하지만, 지불 의사가 있는 고객군은 자동화 성숙도가 제각각이라 표준 템플릿의 제품-시장 적합성이 약할 수 있다. | 수요 지표 하락 |
| 실행 리스크 | 높음: 다수 API 연동, 이벤트 신뢰성, 권한·보안·감사로그, 실패 복구 설계가 필요하며 MVP라도 운영 안정성 요구치가 높다. | 핵심 범위 일정 초과 |
