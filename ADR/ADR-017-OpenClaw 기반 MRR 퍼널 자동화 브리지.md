# ADR-017: OpenClaw 기반 MRR 퍼널 자동화 브리지

## 맥락 (Context)
출처: Track A 쿼리1 @MahmudurRa23483 x(https://x.com/MahmudurRa23483/status/2025573178949709846), @PrajwalTomar_ x(https://x.com/PrajwalTomar_/status/2025496783904969119), @damdev_ x(https://x.com/damdev_/status/2025580797852340480). 제안: OpenClaw로 콘텐츠/DM/리뷰 수집·리마인드 알림을 묶은 '런칭 오케스트레이터'를 셀픽스/내부 운영의 공통 파이프라인으로 확장해 초기 고객 유입·후속 영업 리드를 줄이되, 리포트/대시보드는 실시간 공개.

## 결정 (Decision)
**⏸️ 보류**
- 시장: 보류 — 요구 페르소나(1인 SaaS) 적합도와 반복운영 자동화 필요성은 높아 초기 실험 가치가 있으나, 공개 수요 신호는 계량적 근거가 제한적이고 기능별 대체 솔루션이 조기 분산되어 있다. DM·팔로우 자동화는 정책 제약 리스크로 초기 수익화까지 학습 비용이 발생할 수 있어, 파이프라인 템플릿의 KPI 실험(리드 회수율·MRR 동기화율·응답 전환율)이 확보되기 전 단계적 확장은 보류가 합리적이다.
- 기술: 추천 — OpenClaw 크론·에이전트·토픽 라우팅과 n8n 웹훅/스케줄러 조합은 이미 운영 가능한 구성이라 기술적 실현성이 높다. 핵심 리스크는 SNS 정책 위반 가능성과 외부 API 변동성이므로 DM/팔로우를 승인 큐 기반 반자동으로 제한하면 MVP 범위에서 안정적으로 검증 가능하다.
- 비즈니스: 보류 — 소프트웨어형 구독 마진은 안정적이지만, 핵심 고객이 플랫폼 API 정책·DM 제한·계정 리스크에 강하게 노출되고 유사 대체 툴(e.g., n8n 템플릿, 메이커용 CRM)과의 경쟁이 치열해 단독 차별화 포인트가 제한적이다. 1인 창업자 대상 LTV를 확보하려면 보완 기능(리포팅/교육, 승인형 퍼널)과 정책 대응 가드레일이 먼저 입증되어야 한다.
- Critic: 보류 — 현재는 시장 경쟁과 규제·플랫폼 의존성이 높고, 자동화 정합성(중복/누락/차단)에 대한 핵심 가정이 미검증이어서 즉시 고속 확장보다 파일럿 기반의 Kill Criteria 검증 후 판단이 필요하다.

## 검토한 대안 (Options)
초기 MVP를 ‘MRR 체크 + 리드 추적(1개 채널)’로 축소하고 DM/팔로우 자동은 수동 승인 워크플로우에 두어 정책 리스크를 통제,콘텐츠 배포·팔로우를 채널별 플러그인(예: 트위터/레딧/메일)로 분리해 플랫폼 장애 시 기능 일부만 안전 중단 가능한 아키텍처로 전환,내부 공통 파이프라인 확장은 단계별 릴리즈(한 고객 세그먼트 2주 파일럿→KPI 게이트 통과 후 확장)로 진행

## 트레이드오프 (Consequences)
- 실행 시: 타깃 1인 SaaS 창업자 10~15명 인터뷰로 채널(트위터/X/메일)별 반응속도와 DM 리스크 포인트를 확정한다. → OpenClaw+n8n 최소 스코프(Pipeline 생성, 콘텐츠 배포, 리드 상태 추적, MRR 체크 동기화)를 1개 채널에서 PoC로 구현해 1회 운영 리허설까지 완료한다. → 유료 파일럿 2~3개 계정 온보딩 후 주간 레포트(리드→미팅→수익) 자동화 정확도와 중복/중단발송율을 점검하고 가격/패키지 조정한다.
- 미실행 시: 기회 비용 발생

## 리스크 및 탐지 신호
| 리스크 | 내용 | 탐지 신호 |
|--------|------|-----------|
| 치명적 결함 | 가장 큰 치명결함은 차별화 포인트가 ‘자동화 자체’에 치중되어 있고, 계정 정책 변화나 플랫폼 인터페이스 취약점이 터지면 핵심 기능(발송/추적/리텐션 관제)이 동시에 흔들린다는 점이다. 선순위 검증 없는 상태에서 바로 확장하면 재구축 비용만 커질 가능성이 크다. | 초기 검증 실패 |
| 시장 리스크 | 1인 창업자 대상 자동화 수요는 존재하나 이미 Make/Zapier/n8n 템플릿 및 인플루언서 툴이 활발해 가격·기능 경쟁이 매우 치열하다. 특히 DM/팔로우 자동화는 대체재 대비 진입 장벽이 낮아, 가격 압박과 탈락률 상승 리스크가 높다. | 수요 지표 하락 |
| 실행 리스크 | 실행 위험은 플랫폼 API 제약 대응(할당량, 인증 만료, 정책 변경), 작업 큐 멱등성(중복 발송 방지), MRR 데이터 정합성 보정 체계 부재가 핵심이다. 특히 OpenClaw 내부 파이프라인 확장 단계에서 오케스트레이션 오류가 누적되면 내부 운영과 고객용 기능이 동시에 오염될 가능성이 있다. | MVP 일정 초과 |
