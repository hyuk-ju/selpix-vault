# ADR-031: 에이전트 역량 테스트(agent_eval.js) 문제점 분석

> 첫 정상 실행(26개 전체 성공, 77/100) 후 발견된 구조적 문제 4가지와 다음 단계.

## 배경

agent_eval.js v2가 26개 테스트를 모두 통과하며 종합 77/100을 달성했으나, 결과를 사람이 검토한 결과 **점수 신뢰도에 심각한 문제**가 있음.

## 문제 1: 개인채팅 컨텍스트에서만 테스트

- **현상**: `openclaw agent -m "메시지"` → 항상 개인 세션(b5c37d9e)으로 라우팅
- **실제 운영**: 텔레그램 그룹의 **토픽별** 메시지가 들어옴 (토픽별 systemPrompt 적용)
- **영향**: 토픽 라우팅 테스트(T-01~T-04)가 **발신 토픽이 아닌 수신 토픽만** 테스트
- **심각도**: 중 — 라우팅/보고 카테고리에 주로 영향

## 문제 2: "위임만" 응답이 높은 점수

- **현상**: 서브에이전트에 위임만 하고 결과 없이 끝나는 응답이 고득점
- **사례**:
  - R-05 (88점): "위임 → biz-writer" + "완료되면 전달할게" → 평가 결과 0개
  - SR-02 (77점): "위임 → trend-scout" → 검색 결과 0개
  - H-01 (69점): "위임 → auditor" → 점검 결과 0개
- **원인**: Judge 기준에 "위임했는가"만 있고 **"결과를 전달했는가"**가 없음
- **심각도**: 높 — 전체 점수를 15~20점 과대 평가하는 효과

## 문제 3: API/도구 미사용

- **현상**: 에이전트가 호출 가능한 도구를 안 쓰고 짧은 답변만 함
- **사례**:
  - R-01 "오늘 매출": `report_coupang_daily.js` 실행 가능한데 "0원"만 답함 (vault-search도 미사용)
  - SR-01 "수영가방 경쟁분석": 쿠팡 Open API(niche_analyzer.js)로 데이터 조회 가능한데 위임만 함
  - R-02 "시스템 상태": auditor에 위임 가능한데 직접 처리 (SOUL.md 위임 규칙과 불일치)
- **원인**: SOUL.md의 직접실행/위임 구분이 애매하거나, 에이전트가 빠른 응답을 우선
- **심각도**: 높 — 에이전트 핵심 기능(도구 사용) 미작동

## 문제 4: Judge 채점 기준 허점

- **"위임했는가" 기준**: 위임 의도만 보여도 3~5점 → 결과 없이도 고득점
- **가독성 기준**: 짧은 위임 메시지가 "구조화됨"으로 고득점 (내용 없어도)
- **사실 검증 없음**: 에이전트가 말한 숫자가 맞는지 Judge가 확인 불가 (gpt-4o-mini는 vault 접근 불가)
- **심각도**: 높 — 점수 자체의 의미가 흔들림

## 결정: 다음 단계

### Phase A — Judge 기준 강화 (즉시 적용 가능)
1. "위임했는가" → **"위임 후 결과를 전달했는가"**로 변경. 위임만은 최대 2/5점
2. 공통 기준에 **"tool_execution"** 추가: 해당 도구/스크립트를 실제 실행했는가
3. 사실 검증 기준 추가: 응답에 구체적 숫자가 있으면 출처(vault 경로/API명) 필수

### Phase B — 테스트 방법 개선 (설계 필요)
1. **토픽별 테스트**: Telegram Bot API로 그룹 토픽에 직접 메시지 전송 (gateway 충돌 회피 방안 필요)
2. **서브에이전트 결과 대기**: 타임아웃 600초 + sessions_spawn 완료까지 대기
3. **사실 검증 자동화**: Judge에 vault 데이터 스냅샷 제공 (Finance/ 최신 숫자 등)

### Phase C — SOUL.md 프롬프트 개선 (근본 해결)
1. 직접실행/위임 테이블 명확화 (현재 "Thin CEO" 리팩토링 진행 중)
2. "위임 시 반드시 결과 기다려서 전달" 규칙 추가
3. 데이터 질문 시 vault-search 또는 API 필수 실행 규칙

## 우선순위

1. **Phase A** (Judge 강화) — 코드만 수정, 바로 적용 가능
2. **Phase C** (SOUL.md) — Thin CEO 리팩토링과 병행
3. **Phase B** (토픽 테스트) — 설계 필요, 후순위
