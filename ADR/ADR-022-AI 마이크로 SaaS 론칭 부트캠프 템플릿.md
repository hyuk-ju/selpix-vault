# ADR-022: AI 마이크로 SaaS 론칭 부트캠프 템플릿

## 맥락
source: Track B Nick Saraev CLAUDE CODE FULL COURSE & CLAUDE CODE와 Make/n8n 자동화 전환 영상, Track B 조코딩 바이브코딩 3시간 통합본(Stripe·API 튜토리얼). 비즈니스 전개: 회원가입/결제/알림/후기 수집/콘텐츠 배포 템플릿을 포함한 템플릿팩 SaaS를 월 구독+세팅 컨설팅으로 판매.

## 결정
**✅ 추천 (주의 필요)**
- 시장: 추천 — 시장 관심도는 높고 타깃이 명확하다. 다만 템플릿 경쟁이 빠르게 심화될 수 있어 차별화 구조가 필요하다.
- 기술: 추천 — Node.js + Stripe + 워크플로 자동화 스택으로 구현 가능성이 높다. 다만 결제/권한/오류복구 테스트를 초기에 강하게 설계해야 한다.
- 비즈니스: 보류 — 마진 구조는 좋지만 초기 고객획득 채널이 불명확하면 전환이 막힐 수 있다. 첫 주에는 유입 채널 검증을 병행해야 한다.
- 반대 검증: 보류 — 실행 자체는 가능하지만 가설 검증 전 대규모 확장은 위험하다. 좁은 타깃 파일럿과 명확한 중단 기준이 필요하다.

## 검토한 대안
세그먼트 1개 집중형 마이크로 템플릿으로 시작해 증거 기반 확장

## 트레이드오프
- 실행 시: 핵심 타깃 1개(예: 1인 개발자)로 포지셔닝 고정 및 랜딩 문구 확정 → 결제 포함 MVP 판매 페이지 오픈 + 5명 베타 유치 → 베타 피드백 기반 템플릿/가격 패키지 2안 AB 테스트
- 미실행 시: 기회 비용 발생

## 리스크 및 탐지 신호
| 리스크 | 내용 | 탐지 신호 |
|--------|------|-----------|
| 치명적 결함 | 콘텐츠형 경쟁자(강의/커뮤니티)와 가격 비교에서 우위가 약할 수 있음,고객 세그먼트가 넓으면 메시지가 흐려져 전환 효율 하락,초기 성공 사례 부족 시 신뢰도 형성이 느림 | 초기 검증 실패 |
| 시장 리스크 | 콘텐츠 과포화로 유사 제안이 빠르게 복제될 가능성 | 수요 지표 하락 |
| 실행 리스크 | 결제/권한/자동화 연결 실패 시 초기 사용자 이탈이 큼 | 핵심 범위 일정 초과 |
