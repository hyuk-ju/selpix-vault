# ADR-20260408-인텔토론

## Decision
- 수납 정리템 YouTube 모니터링 쿼리 추가: **deferred**
- 이어폰 수요 워치카드 추가: **deferred**
- 요가매트 파생어 동의어 확장: **rejected**
- 자동 적용 건수: **0건**

## Assumptions
- SYSTEM_STATE.md 기준 인텔 루프는 운영 안정 우선이며 `update_fee_table` 자동 적용은 금지다.
- 최근 3일 내 확인 가능한 인텔 ADR 파일은 실질적으로 `ADR-20260403-인텔토론.md` 계열 참조가 핵심이었다.
- `build_intel_briefing.js`는 샌드박스 절대경로 제약으로 직접 실행 실패해, 동일 소스 데이터로 `data/intel_briefing.json`을 복원했다.
- biz/ops 평가 파일은 생성되었지만 proposal 세트와 제목 정합성이 맞지 않아 안전한 3자 합의로 보기 어렵다.

## Options
1. 수납 정리템 쿼리 추가 즉시 적용
   - 장점: 리빙/수납 신호를 빠르게 더 포착 가능
   - 단점: 평가 정합성 깨진 상태에서 자동 반영은 위험
2. 이어폰 워치카드 즉시 적용
   - 장점: 디지털/가전 상승 신호 대응 가능
   - 단점: 합의 파일 불일치로 자동화 신뢰도 낮음
3. 이번 루프는 보류/거부 처리
   - 장점: 운영 안정성 유지, 잘못된 자동 적용 방지
   - 단점: 탐색 속도는 느려짐
- **채택:** 3번

## Risks
- 평가 파일 정합성 불일치 상태에서 자동 적용 시 잘못된 타깃 수정 가능성
- 최근 3일 유사 제안 재승인 시 중복 모니터링 증가
- 브리핑 스크립트 절대경로 의존이 지속되면 크론 안정성 저하 가능

## Next Actions
- intel 평가 서브에이전트 프롬프트를 proposal 세트 고정 참조 방식으로 보정
- `build_intel_briefing.js`의 절대경로 의존 제거 또는 샌드박스 경로 대응 검토
- 다음 루프에서 수납 정리템, 이어폰 신호를 동일 proposal ID 기준으로 재평가
