# ADR: 자동 코딩 파이프라인 UI/UX 품질 개선

## 맥락

OpenClaw 자동 코딩 파이프라인(`run_coding_execution.js`)이 생성하는 프로젝트의 UI/UX 퀄리티가 데모 수준으로 낮음.

`dialogic-roadmap` 프로젝트 분석 결과:
- CSS 2벌 (SPA용 + MPA용)
- SPA/MPA 이중 구조 (동일 기능 중복)
- JSON.stringify 직접 출력
- 반응형/접근성 미구현
- `<a>` 안에 `<button>` 중첩

## 근본 원인

1. `coding_spec.features[]`가 백엔드만 나열 → UI 스텝 미생성
2. Acceptance criteria가 `"기능 구현 및 동작 확인"` 한 줄 → UI 기준 없음
3. 프론트엔드 라운드가 별도 실행되며 이전 산출물 정리 안 함
4. Claude Bridge review 프롬프트에 UI 체크 항목 없음

## 결정

### 변경 1: 프론트엔드 UI 스텝 자동 추가
- `run_coding_execution.js` — Full 모드에서 feature 스텝 후 `type: 'frontend'` 스텝 자동 삽입
- 6개 UI acceptance criteria 포함

### 변경 2: Feature acceptance 강화
- 각 feature의 acceptance에 `"UI가 포함된 경우: 기존 CSS와 통합"` 추가

### 변경 3: Instruction에 frontend 타입 지원
- `generateInstruction()`에 `type === 'frontend'` 분기 추가
- CSS 통합, JSON 출력 금지, 반응형 등 필수 규칙 명시

### 변경 4: Claude Bridge review UI 체크
- review 시스템 프롬프트에 CSS 중복, 시맨틱 HTML, JSON 출력, 반응형 체크 추가

## 영향 범위

| 파일 | 변경 |
|------|------|
| `scripts/run_coding_execution.js` | 스텝 생성 + instruction 생성 로직 |
| `scripts/lib/claude_bridge.js` | review 시스템 프롬프트 |
