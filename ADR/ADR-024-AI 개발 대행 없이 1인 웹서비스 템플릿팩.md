# ADR-024: AI 개발 대행 없이 1인 웹서비스 템플릿팩

## 맥락 (Context)
source: 조코딩("AI News - ...") + 조코딩("바이브 코딩 1인 창업 3시간 통합본") + Nick Saraev("Gemini 3.1 Pro + Antigravity ...")에서 반복적으로 강조한 API 기반 신속 빌드 방식. 실행안: 템플릿+강의형 SaaS 번들(인증·결제·오퍼레이션 포함)로 전환해 초기 진입비용을 낮추고, 월 구독/템플릿 판매/개발대행 업셀링으로 수익화.

## 결정 (Decision)
**⏸️ 보류**
- 시장: 보류 — 수요는 존재하고 문제 적합도도 높으나, 이미 유사 템플릿팩/노코드·에이전트 템플릿 시장이 포화되어 가격 경쟁 위험이 큽니다. 우선은 유료 전환 데이터를 확보할 수 있는 좁은 ICP(예: 특정 업종/기능)로 MVP를 제한하고, 배포 성공률·QA 비용·초기 LTV를 검증한 뒤 단계 확장하는 쪽이 안전합니다.
- 기술: 추천 — 기술적 불확실성은 낮고(검증된 조합), 1인 개발로도 MVP 출시가 가능하다. 성공 관건은 난개발이 아니라 설치 성공률과 문서 품질이며, 이는 단계적 파일럿으로 빠르게 개선 가능하다.
- 비즈니스: 보류 — 수요 자체는 높지만 템플릿 시장 포화로 진입 장벽이 낮고, 가격 경쟁이 심해 단가 하향 압박이 크다. '템플릿팩'이 실제 수익화를 끌어내려면 고객군을 수평적이 아니라 특정 니즈(예: SaaS 스타트업 랜딩+정산 세트, 구독형 운영형)로 더 좁히고 실행 증거와 케이스를 쌓은 뒤 재평가하는 것이 안전하다.
- Critic: 보류 — 아이디어 자체의 방향성은 타당하지만, 경쟁 밀집도와 운영 책임 비용이 커서 현재 구간에서는 즉시 상용 확장 판단이 성급하다. 특히 수익화 가정(구매 전환, 장기 유지율), 결제·배포 안정성, 고객지원 부하의 근거가 검증되지 않아 우선 파일럿 게이트(전환율·지원량·SLA) 통과 후 재판정이 필요하다.

## 검토한 대안 (Options)
전체 SaaS 템플릿 판매를 바로 추진하지 말고, 특정 수직(예: 상담형 서비스, 소규모 예약형 SaaS) 1개 니치로 MVP를 축소한 뒤 템플릿+세팅대행 패키지로 시작한다.,템플릿 판매 대신 ‘템플릿 기반 구축 대행 + 월 운영 지원’ 모델로 먼저 시작해 지원 비용 구조와 이탈/환불 패턴을 실측한 뒤, 안정된 프로덕트화 항목만 상품화한다.,기존 비슷한 대안 대비 차별화를 위해 템플릿 단품보다 ‘실행 템플릿 + 체크리스트 + 30일 운영 가드레일(알람/백업/보안 점검)’ 번들로 가치를 고정화한다.

## 트레이드오프 (Consequences)
- 실행 시: 타깃(1인 AI 창업가/개인 운영자) 30명 인터뷰로 급한 니즈를 4개 카테고리(랜딩, 결제, 운영 자동화, 배포)로 압축하고, 제안 가치를 '3시간 내 MVP 공개'로 구체화한 랜딩 페이지와 대기명단 페이지를 오픈한다. → 핵심 템플릿 2종(MVP 구축, 결제 연동, 운영 운영체크리스트)만 포함한 MVP 번들을 공개한다. 유료 얼리버드 50명 타깃으로 가격 민감도(A/B 9,900~29,000원)와 전환 문구를 실험해 CAC, 전환율, 재방문율을 1차 측정한다. → 구독 플랜(Starter/Pro)과 템플릿 단품 결제 경로를 결제·정산 자동화하고, 가입 즉시 실행 가능한 가이드를 제공한다. 1:1 셋업 지원은 템플릿 커스터마이징 지원권으로 전환해 유료 전환을 유도하고, 7일째 지표 점검 후 메시지 자동화(온보딩/리마인드) 가동한다.
- 미실행 시: 기회 비용 발생

## 리스크 및 탐지 신호
| 리스크 | 내용 | 탐지 신호 |
|--------|------|-----------|
| 치명적 결함 | 1인 웹서비스 템플릿 수요는 존재해도, 구매 결정권자(개인 창업자)는 가격 민감도가 높아 경쟁 No-code/프리랜서 대안 대비 차별화가 약하면 초기에 쉽게 이탈한다.,템플릿 제공은 끝이 없고, 실제 가치는 ‘초기 구축’보다 ‘장기 운영 안정성(결제 연동, 모니터링, 장애 대응)’에 의해 좌우되는데 이 운영 레이어가 현재 설계되지 않았다.,초기 대상군의 기술 역량 편차가 커서 동일 템플릿이 과도한 사용자별 커스터마이징 요구를 유발하고, 오히려 지원 비용이 매출을 잠식할 가능성이 큼. | 초기 검증 실패 |
| 시장 리스크 | 시장 리스크는 ‘수요 부재’보다 ‘차별화 미흡’이 핵심이다. 기존 템플릿/빌드 스택 시장이 이미 촘촘해 가격 압박이 크고, 동일한 니즈를 무료/저가 도구로 대체하려는 경향이 강하다. | 수요 지표 하락 |
| 실행 리스크 | 실행 리스크는 결제·배포·LLM 비용 통제·고객 지원의 네 갈래에서 높다. 특히 초기엔 고객군의 기술 편차가 커 배포 성공률 관리 비용이 급증하고, API/플랫폼 변화 대응 속도가 늦어지면 체감 가치가 급락한다. | MVP 일정 초과 |
