# 벨류팩(Value Pack) 도입 가이드

## 목적
벨류팩은 사람이 읽기 좋은 문서가 아니라, **에이전트가 안정적으로 검색·판단·인용하기 좋은 지식 단위**다.

## 왜 도입하나
- RAG 검색 후 바로 행동 규칙으로 쓰기 쉽다.
- 문서마다 구조가 달라도, 판단용 문서만큼은 포맷을 고정할 수 있다.
- `confidence_level`, `status`, `source_agent` 같은 메타데이터를 일관되게 붙여 신뢰도 관리가 쉬워진다.
- 향후 검색 후처리(예: high confidence 우선, deprecated 제외)에 유리하다.

## 벨류팩 설계 원칙
1. 한 벨류팩 = 한 판단 주제
2. 자유서술보다 고정 필드 우선
3. 기존 RAG 파서가 읽는 키를 유지한다
4. 검색 엔진 score와 문서 신뢰도 필드를 혼동하지 않는다
5. 기존 문서는 일괄 마이그레이션하지 않는다

### 기존 파서 호환 필드 (유지 권장)
- `title`

- `source_agent`
- `confidence_level`
- `created`
- `note_status`
- `tags`
- `status`

### 확장 필드 (선택)
- `last_verified`
- `rule_scope`
- `evidence_paths`

## 권장 본문 구조
- `summary`: 한 줄 핵심 판단
- `decision`: 채택할 규칙/판단
- `evidence_paths`: 근거 문서 경로
- `exceptions`: 예외 조건
- `action_rule`: 실제 행동 규칙
- `## evidence`: 핵심 근거 메모
- `## notes`: 보충 메모

## 기존 문서 조치 원칙
### 1. 그대로 유지
아래 문서는 우선 건드리지 않는다.
- 일반 프로젝트 문서
- 리서치 원문
- 일지/히스토리
- 설명형 보고서

### 2. 벨류팩으로 "추가" 생성
아래 문서는 원문을 고치기보다, 별도 벨류팩을 붙이는 방식이 적합하다.
- 자주 참조되는 운영 규칙
- 매출/정산/정책처럼 반복 질의가 많은 문서
- 에이전트가 행동 규칙으로 바로 써야 하는 문서

### 3. 점진 정리 대상
아래 문서는 필요 시 frontmatter만 보완한다.
- frontmatter가 없는 25개 문서
- `confidence_level` 또는 `source_agent`가 빠진 핵심 운영 문서
- `status`가 없어서 활성/폐기 구분이 안 되는 문서

## 권장 마이그레이션 순서
1. 새 판단 문서부터 벨류팩 템플릿 적용
2. 반복적으로 검색되는 운영 규칙만 벨류팩 별도 생성
3. 검색 품질 확인 후 핵심 문서 일부만 메타데이터 보강
4. 마지막에만 인덱서 파서 확장 검토
