# Runbook: 텔레그램 전송 실패

## 증상 (Symptoms)
- 콘솔 로그: `fetch retry 1/3: fetch failed`
- 알림/리포트가 텔레그램에 도착하지 않음
- `sendMessage error:` 또는 `sendDocument FAILED` 로그

## 재현 절차 (Steps to Reproduce)
1. 서비스 상태 확인:
   ```bash
   systemctl --user status openclaw-gateway.service
   ```
2. 환경변수 확인:
   ```bash
   grep TELEGRAM /home/dev/openclaw/.env
   ```
3. 수동 테스트:
   ```bash
   curl -s "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/getMe" | jq .ok
   ```

## 해결 절차 (Resolution)

### fetch failed (DNS/네트워크)
- 첫 요청 실패는 **정상 동작**. telegram.js의 fetchRetry가 3회 재시도 (2s, 4s, 6s 백오프)
- 3회 모두 실패하면 네트워크 이슈:
  1. DNS 확인: `dig api.telegram.org`
  2. 서버 방화벽/네트워크: `curl -I https://api.telegram.org`
  3. autoSelectFamily 설정: openclaw.json의 `network.autoSelectFamily: false` 확인

### 봇 토큰 만료/차단
- `getMe` 응답이 `ok: false` → 토큰 재발급 필요 (@BotFather)
- .env의 `TELEGRAM_BOT_TOKEN` 교체 + 서비스 재시작

### sendDocument 실패 (파일 크기)
- 텔레그램 파일 업로드 제한: 50MB
- HTML 리포트는 보통 수 KB라 문제 없음
- 로그에 `(${fileSizeKB}KB)` 확인

## 체크리스트 (Post-Resolution)
- [ ] `curl getMe` 정상 응답 확인
- [ ] 다음 크론 실행 시 텔레그램 전송 성공 확인
- [ ] 3회 재시도 후에도 실패하면 네트워크 팀 확인

## 히스토리 (과거 발생 이력)
- 첫 fetch 실패는 서버 DNS 캐시 문제로 빈번 발생 (정상, fetchRetry로 복구됨)
