# 시스템 상태 점검 규칙

summary: 시스템 상태 질문은 추측하지 말고 SYSTEM_STATE.md + 실시간 상태 명령 + 관련 점검 스크립트를 근거로 판단한다.
decision: 상태/헬스/오류 질문은 최소 체크셋 확인 후 답하고, 불일치 시 추측 대신 불확실 또는 위험으로 보고한다.
evidence_paths:
  - SYSTEM_STATE.md
  - scripts/system_auditor.js
  - scripts/pipeline_health_check.js
exceptions:
  - 단순 개념 설명은 실시간 점검 없이 대화로 처리할 수 있다.
  - 시스템 진단/상태 보고는 반드시 실행 증거를 동반해야 한다.
action_rule:
  - 상태 질문을 받으면 먼저 SYSTEM_STATE.md를 확인한다.
  - 실시간 상태가 필요하면 openclaw status 또는 관련 스크립트를 직접 실행한다.
  - 파이프라인 질문은 pipeline_health_check, 시스템 전반은 system_auditor 결과를 우선한다.
  - 결과는 🟢/🟡/🔴 신호와 함께 근거 기반으로 요약한다.

## evidence
- SYSTEM_STATE.md는 상태 추측 방지용 필수 참조 문서로 명시돼 있다.
- AGENTS/SOUL 규칙상 시스템 상태 추측 보고는 금지이며, 실행 후 답해야 한다.
- system_auditor.js와 pipeline_health_check.js는 각각 시스템 전반 및 파이프라인 상태의 표준 점검 스크립트다.

## notes
- 상태 질문 키워드에 따라 최소 체크셋을 다르게 적용한다.
- 상태가 불일치하면 추가 점검 필요를 명시하고 단정하지 않는다.
