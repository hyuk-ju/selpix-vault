## 🔔 인텔 승인 시스템 (HITL)

AI 에이전트 3명(트렌드 분석가 / 비즈니스 기획자 / 기술 엔지니어)이 매일 토론해서 파이프라인 변경을 제안합니다.

**위험도에 따라 처리 방식이 다릅니다:**

| 위험도 | 예시 | 처리 방식 |
|--------|------|----------|
| 낮음 | 키워드 추가, 블랙리스트 | 자동 적용 (알아서 함) |
| 중간 | 소싱 배수 변경 | 텔레그램 버튼으로 승인 요청 |
| 높음 | 트렌드 키워드 추가 | 텔레그램 버튼으로 승인 요청 |
| 차단 | 수수료 테이블 변경 | 어떤 경우에도 자동 적용 불가 |

**텔레그램에서 버튼이 오면:**
- ✅ 승인 → 바로 적용됨
- ❌ 거절 → 적용 안 함

**대기 목록 확인하고 싶으면:**
텔레그램에서 에이전트한테 "승인 대기 목록 보여줘" 라고 하면 됩니다.

**안전장치:**
- 적용 전 자동 백업 (.bak 파일)
- 적용 후 코드 문법 검증 → 에러 시 자동 복원 + 텔레그램 알림
- `intel_apply_log.json`에 최근 500건 기록 유지

## 쿠팡 API 핵심 규칙

- **NUMBER 속성**: 단위 접미사 필수 (`100` → `100g`)
- **groupNumber 중복**: 같은 groupNumber면 하나만 전송
- **가격 계산**: `perUnitCost = price + shipping/minOrder` (개당 원가!)
- **상품 수정**: GET → merge → PUT 전체 payload (부분 업데이트 불가)
- **full PUT**: 수정 PUT에는 항상 `requested: true` 유지
- **임시저장 복구**: GET → PUT 재전송
- **판매 재개**: `PUT vendor-items/{id}/sales/resume`
- **판매중지 후 삭제**: `sales/stop` 먼저 → DELETE
- **MOQ 동기화**: 쿠팡 GET에 `minimumQuantity`가 비어 있으면 `1`로 단정하지 않고 queue/source 기준으로 비교
- **원본 데이터 없음**: 승인완료 상품이라도 도매꾹 원본 검증 불가 시 운영상 판매중지 후 `stock_stopped` 처리
- **해외직배송**: 자동 복구/동기화 대상에서 제외하고 `보류` 유지
