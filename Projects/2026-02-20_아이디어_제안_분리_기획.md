# 아이디어 제안 방(UI UX) 분리 기획안

## 1. 개요 (As-Is)
현재 **일일 브리핑(텍스트)**과 **아이디어 제안(버튼)**이 모두 `TOPIC 29 (REPORTS)` 방으로 전송되고 있습니다.
- `daily-briefing` 크론 완료 시 -> 29번 방으로 텍스트 요약 발송
- `save_idea.js` 스크립트 실행 시 -> 29번 방으로 승인 버튼 발송
- 텔레그램 채팅 중 `escalate_idea.js` 실행 시 -> 29번 방으로 승인 버튼 발송

이로 인해 "읽기 전용 보고서"와 "사용자 액션을 요구하는 제안(버튼)"이 한 곳에 섞여 UX가 비효율적이며, 향후 아이디어가 쌓일수록 브리핑이 묻히는 문제가 발생합니다.

## 2. 해결 방안 (To-Be)
사용자의 액션(승인/거절)이 필요한 **"아이디어 제안 버튼"**의 수신처를 일일 리포트 방에서 **아이디어 처리 전용 방**으로 완전히 분리합니다.

### 🔄 분리 파이프라인
1. **읽기 전용 보고서 (텍스트)**: 일일 브리핑 리포트는 원래대로 **토픽 29 (REPORTS)** 로 발송
2. **아이디어 제안 버튼**: `save_idea.js`와 `escalate_idea.js`의 목적지를 **아이디어 전용 토픽**으로 전환

## 3. 구체적인 작업 범위 (Action Items)

### 🛠 수정 대상 스크립트
1. `scripts/save_idea.js`
   - Telegram 발송 시 옵션 `threadId`를 지정하는 부분을 `TOPIC.REPORTS`에서 지정된 새로운 타겟으로 수정.
2. `scripts/escalate_idea.js`
   - Telegram 발송 시 `threadId` 옵션을 `TOPIC.REPORTS`에서 지정된 새로운 타겟으로 수정.

### 🤖 추가 점검 (브리핑 크론)
- 29번 방에 전송되는 일일 브리핑 텍스트 하단에 *"💡 오늘의 제안은 아이디어 실험실(또는 제안실)에 발송해 두었습니다."* 라는 형태의 간략한 안내 텍스트 추가 (UX 관점)

## 4. 검토 포인트 (선택 필요)

새로운 아이디어 제안 안건(버튼)이 올라갈 방을 다음 두 가지 중 결정해야 합니다:

* **[1안] 177번 (아이디어 실험실) 방으로 병합**
  - 장점: 안건 제안부터 -> 제안된 버튼 -> 에이전트들의 심층 토론 -> 최종 결과 카드 발송까지 **한 방에서(177) 전부 이어집니다.** 파편화를 줄일 수 있습니다. (추천)
* **[2안] 282번 (아이디어 대시보드) 방으로 분리**
  - 장점: 282번 방은 오직 "버튼(제안)들만 쌓여있는 제안함"으로 쓰고, 여기서 버튼을 눌러 승인(Discussing) 된 안건들만 177번(실험실) 방으로 넘어가서 토론이 진행되게 합니다. 

사용자분께서 **1안과 2안 중 더 선호하시는 구조**를 말씀해 주시면, 해당 토픽 ID 상수를 스크립트에 즉시 반영하겠습니다.
