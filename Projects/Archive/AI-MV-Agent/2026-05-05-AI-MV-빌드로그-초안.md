## 빌드로그 아웃라인

### Problem

뮤직비디오 편집자의 첫 병목은 완성본 자동 생성이 아니라, 많은 테이크 속에서 “지금 타임라인에 올릴 후보 컷”을 빠르게 찾는 일이다. 개발자/기술 편집자에게는 블랙박스 생성기보다 로컬에서 재현 가능한 clip triage → 검색 → FX 추천 → FCPXML handoff 흐름이 더 신뢰를 만든다.

### What changed

최근 Daily note의 초점이 구현 추가가 아니라 `no-media demo`를 포트폴리오 자산으로 포장하는 쪽으로 고정됐다. README는 이미 `mv-brain demo` → `mv-brain serve` → UI clip browser/output 확인이라는 첫 실행 흐름을 제공한다. 이번 빌드로그는 “실제 영상이나 API 키 없이도 제품의 끝점이 FCPXML이라는 것을 보여주는 데모”를 중심 메시지로 삼는다.

### Technical detail

개발자에게 보여줄 핵심은 세 가지다.

1. `mv-brain demo`는 샘플 클립 메타데이터와 `output/demo_roughcut.fcpxml`을 생성해, provider 없이도 제품의 입출력 경계를 보여준다.
2. 검색/추천의 장기 구조는 `visual`, `audio`, `style` 3-channel embedding으로 나뉜다. 즉, 화면에 보이는 것, 음악 에너지, 편집상 쓸만함을 분리해 검색한다.
3. UI/CLI의 결과는 채팅 응답에서 끝나지 않고 Final Cut Pro가 받을 수 있는 FCPXML 파일로 이어진다.

### Demo angle

짧은 개발자 데모는 60~90초면 충분하다.

1. 터미널: `mv-brain demo` 실행 후 생성 파일 경로를 보여준다.
2. 로컬 앱: `mv-brain serve` 후 clip browser, 자연어 검색 예시, FX 추천 예시를 보여준다.
3. Output: `output/demo_roughcut.fcpxml`이 생성되어 Final Cut Pro handoff 지점까지 연결된다는 점을 보여준다.

### Next experiment

README 또는 `docs/public/overview.*.md`에 넣을 3컷 스토리보드를 만든다: 샘플 클립 브라우저, 자연어 검색/FX 추천, `demo_roughcut.fcpxml` output 확인. 목표는 GitHub 방문자가 60초 안에 “이 프로젝트는 local-first clip triage assistant이고, 결과물이 편집 타임라인으로 넘어간다”는 점을 이해하게 만드는 것이다.
