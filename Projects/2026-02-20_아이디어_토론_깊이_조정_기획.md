# 아이디어 실험실 토론 깊이 조정 (Fast Track) 기획안

## 1. 개요 (As-Is)
현재 `run_idea_discussion.js`는 제안된 아이디어의 `type`에 관계없이 무조건 **4단계 심층 토론 (시장/trend -> 기술/tech -> 비즈니스/biz -> 비판/critic)**을 거칩니다.
- `standalone` (독립 SaaS), `selpix` (쇼핑몰 수익화) 등 외부 시장을 타겟으로 하는 아이디어에는 이 4단계 검증이 필수적입니다.
- 하지만 `openclaw` (내부 시스템 업데이트, 파이프라인 리팩토링 등)와 같은 내부 유지보수/고도화 작업에도 동일한 잣대(시장 규모, 마진율, 타겟 고객 등)를 들이대어 불필요한 컴퓨팅 자원과 에이전트 스킬이 낭비되고 있습니다.

## 2. 해결 방안 (To-Be)
아이디어의 `type` 속성에 따라 토론 파이프라인(Phase)을 동적으로 분기하는 **Fast Track (빠른 검증) 모드**를 도입합니다.

### 🛣️ 트랙 분리 전략

**[트랙 A] 정규 심층 토론 (Full Discussion)**
- 대상: `type === 'standalone'` 또는 `type === 'selpix'`
- 참여 에이전트: `trend-scout` -> `ops-dev` -> `biz-writer` -> `main` (Critic)
- 목적: 철저한 비즈니스 모델, 시장성, 투자 대비 수익성(ROI) 분석

**[트랙 B] 내부 고도화 빠른 검증 (Fast Track)**
- 대상: `type === 'openclaw'` 
- 참여 에이전트: `ops-dev` (기술/구현 분석) -> `main` (Critic/보안/안정성 검토)
- 스킵: `trend`(시장 분석), `biz`(비즈니스 분석) 단계는 자동으로 패스(Skipped) 처리
- 목적: 내부 구조 개선, 크론 스크립트 작성 등 기술적 타당성과 시스템 안정성만 빠르게 리뷰

## 3. 구체적인 작업 범위 (Action Items)

### 🛠 1. `run_idea_discussion.js` 스크립트 수정
1. **세션 초기화 (`initSession`) 변경**:
   - `type`이 `openclaw`인 경우, `trend`와 `biz` phase의 상태를 초기 생성 시점부터 `skipped`로 설정.
2. **Phase 상태 출력 및 진행 변경**:
   - `skipped` 상태인 phase가 있다면, 대시보드나 텔레그램 진행 알림 시 총 단계 수(현재 4단계)를 유연하게 표시하거나, "Skipped"임을 명시.
3. **토론 결과 카드 생성 (`--finalize`) 변경**:
   - 최종 카드를 만들 때, `trend`와 `biz`가 없으면 빈 칸이 아니라 "내부 고도화 트랙 (시장/비즈니스 검증 생략)" 이라는 문구를 삽입하도록 템플릿 수정.

### 🤖 2. `AGENTS.md` (오케스트레이터 지침) 수정
- 오케스트레이터(아이디어 실험실 관리자) 역할을 하는 에이전트가 `type`에 따라 분기된 스크립트의 동작을 이해할 수 있도록 아이디어 콜백 처리 문서를 업데이트.
- `openclaw` 타입인 경우 `--phase ... trend`를 억지로 실행하지 않고 바로 `tech`부터 시작하도록 지침 명확화.

## 4. 기대 효과
* 내부 시스템 업데이트(OpenClaw) 제안 시 불필요한 시장성/비즈니스 분석을 건너뛰어 에이전트의 토큰 비용과 컴퓨팅 자원(크롤링, 검색 등 스킬 사용)을 획기적으로 절약합니다.
* 내부 고도화 작업의 의사결정 속도가 빨라집니다.
* 외부 수익화 아이디어에는 여전히 강력한 4단계 검증을 유지하여 퀄리티를 보장합니다.
