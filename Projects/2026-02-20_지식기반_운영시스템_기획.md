# 🧠 지식 기반 운영 시스템 — 에이전트 협업 규격화 기획안

> **상태: 📝 기획 (코드 수정 전)**
> 에이전트 토론의 산출물을 규격화하고, 옵시디안 Vault를 "검색 가능한 메모장"이 아닌 **"에이전트들이 같은 언어로 협업하는 지식 운영 인프라"**로 격상시키기 위한 기획.

---

## 1. 문제 인식

### 1-1. 토론은 있지만 결정은 없다
현재 에이전트 토론 시스템(`intel-discussion-loop`, `run_idea_discussion.js`)은 **의견 나열**에 그치고 있다.
- "결론이 뭐야?" → 명확하지 않음
- "왜 이걸 골랐어?" → 버린 대안이 기록 안 됨
- "실패하면?" → 리스크 분석 없음
- "다음에 누가 뭘 해?" → 책임 소재 없음

### 1-2. 옵시디안은 검색이 아니라 규격이 승부처
현재 Vault에 쌓이는 문서는 자유 형식이라:
- 에이전트가 과거 결정을 참조할 때 **무엇이 확정이고 무엇이 검토 중인지** 구분 불가
- 장애가 터져도 **재현 절차가 기록된 곳**이 없음
- 프롬프트를 바꿔도 **이전 버전과 비교할 수 없음**

---

## 2. 결정 템플릿 (Decision Record Template)

모든 에이전트 토론의 출력은 **무조건** 아래 5개 필드를 포함해야 한다:

```markdown
## Decision Record — {주제} ({날짜})

### 1. Decision (확정 결론)
- 이번 라운드에서 확정된 결론 1~3개

### 2. Assumptions (가정)
- [확실] ...
- [가정] ... ← 불확실하면 반드시 "가정"이라고 명시
- [미검증] ...

### 3. Options Considered (검토한 대안)
| 대안 | 요약 | 버린 이유 |
|------|------|-----------|
| A안 | ... | ... |
| B안 | ... | ... |

### 4. Risks (실패 시나리오 Top 3)
| 리스크 | 탐지 신호 | 대응 방안 |
|--------|-----------|-----------|
| ... | ... | ... |

### 5. Next Actions
| 액션 | 담당 | 완료 조건 |
|------|------|-----------|
| ... | ... | ... |
```

### 적용 대상
| 시스템 | 현재 출력 | 변경 계획 |
|--------|-----------|-----------|
| `run_idea_discussion.js` → `--finalize` | 분석 카드 (평가 점수 위주) | **Decision Record 섹션 추가** |
| `intel-discussion-loop` 크론 프롬프트 | 자유 형식 토론 → `intel_decision.json` | **프롬프트에 5필드 출력 강제** |
| `vault/Research/Discussion/*.md` | 자유 마크다운 | **ADR 노트 포맷 강제** |

## 3. Vault 4종 노트 체계

### 노트 타입 및 저장 경로

| 노트 타입 | 용도 | 저장 경로 | 생성 트리거 |
|-----------|------|-----------|-------------|
| **Spec** | 요구사항 / 범위 / 비범위 / 성공조건 / API 계약 | `vault/Specs/` | 새 기능 기획 시 |
| **ADR** | 결정 이유, 검토한 대안, 트레이드오프 | `vault/ADR/` | 토론 종료 시 (자동) |
| **Runbook** | 장애/에러 재현, 해결 절차, 체크리스트 | `vault/Runbooks/` | 장애 발생 시 (의무) |
| **Dataset/Prompt** | 프롬프트 버전, 평가셋, 실패 케이스 | `vault/Prompts/` | 프롬프트 변경 시 |

### 노트별 필수 프론트매터

```yaml
---
type: spec | adr | runbook | prompt
status: draft | active | deprecated
created: YYYY-MM-DD
updated: YYYY-MM-DD
owner: main | trend-scout | ops-dev | biz-writer
tags: [...]
related: [[...]]
---
```

### 각 노트 템플릿

#### Spec 노트
```markdown
# Spec: {기능명}
## 요구사항
## 범위 (In Scope)
## 비범위 (Out of Scope)
## 성공 조건
## API 계약 (입출력 스키마)
## 관련 ADR
```

#### ADR 노트
```markdown
# ADR-{번호}: {결정 제목}
## 맥락 (Context)
## 결정 (Decision)
## 검토한 대안 (Options)
## 트레이드오프 (Consequences)
## 리스크 및 탐지 신호
## 관련 Spec / Runbook
```

#### Runbook 노트
```markdown
# Runbook: {장애/절차명}
## 증상 (Symptoms)
## 재현 절차 (Steps to Reproduce)
## 해결 절차 (Resolution)
## 체크리스트 (Post-Resolution)
## 히스토리 (과거 발생 이력)
```

#### Dataset/Prompt 노트
```markdown
# Prompt: {프롬프트명} v{버전}
## 변경 사유
## 이전 버전과의 차이 (diff)
## 평가 결과 (성공률, 실패 케이스)
## 롤백 조건
```

## 4. 저장 규칙 자동화

| 이벤트 | 자동 액션 | 구현 위치 |
|--------|-----------|-----------|
| 토론 종료 (`--finalize`) | → ADR 노트 자동 생성 | `run_idea_discussion.js` |
| `intel-discussion-loop` 완료 | → ADR 노트 자동 생성 | 크론 프롬프트 + `apply_intel.js` |
| 코드 변경 (파이프라인 스크립트) | → 영향받는 Spec/Runbook에 변경 이력 기록 | AGENTS.md 규칙 / SOUL.md 지침 |
| 장애 발생 (health-check 알림) | → Runbook 먼저 업데이트 후 수정 | `pipeline_health_check.js` 후처리 |
| 크론 프롬프트 변경 | → Prompt 노트 버전 기록 | AGENTS.md 규칙 |

## 5. 가드레일 3개 (즉시 적용)

### 🛡️ Guard 1: Critic은 항상 마지막 발언권
> **승인 없이는 merge/적용 금지**

- `run_idea_discussion.js`: critic이 "반대"면 최종 판정 1단계 하향 ← **이미 구현됨** ✅
- `intel-discussion-loop`: `apply_intel.js`에서 `update_fee_table`은 절대 자동 적용 금지 ← **이미 구현됨** ✅
- **추가 필요:** 모든 에이전트 토론 프롬프트에 "critic의 반대 사유를 해소하지 않으면 적용 불가" 규칙 명시
- **AGENTS.md에 추가:** "토론 결과의 최종 적용은 Critic 판정이 '추천' 또는 '보류'일 때만 허용. '반대'인 경우 사용자 HITL 승인 필수."

### 🛡️ Guard 2: 테스트 없으면 기능 완성 인정 금지
> **최소 재현 스크립트 1개 필수**

- 모든 파이프라인 스크립트 변경 시 `--dry-run` 또는 모의 실행 결과를 로그로 남길 것
- **AGENTS.md에 추가:** "코드 변경 후 반드시 1회 이상 테스트 실행 결과를 Vault에 기록. 기록이 없는 변경은 미완성으로 간주."
- **Runbook 연동:** 테스트 실패 시 Runbook에 실패 케이스 자동 추가

### 🛡️ Guard 3: 옵시디안에 남지 않으면 존재하지 않는 결정
> **기록 없는 합의는 폐기**

- 모든 토론/기획/결정은 Vault에 노트가 존재해야만 유효
- **AGENTS.md에 추가:** "텔레그램이나 세션 내 구두 합의는 Vault에 ADR/Spec으로 기록되기 전까지 효력 없음."
- **크론 프롬프트에 추가:** 토론 종료 시 Vault 저장이 실패하면 텔레그램에 "⚠️ 결정 미기록 — Vault 저장 실패. 이 결정은 무효." 경고 발송

## 6. 구현 계획 (우선순위)

### Phase A: 토대 구축 (AGENTS.md + SOUL.md 규칙 추가)
1. AGENTS.md에 가드레일 3개 규칙 명문화
2. SOUL.md에 "토론 산출물 5필드 템플릿" 프로토콜 추가
3. Vault에 4종 노트 폴더 생성 (`Specs/`, `ADR/`, `Runbooks/`, `Prompts/`)

### Phase B: 토론 시스템 출력 개조
1. `run_idea_discussion.js` — `buildVaultMarkdown()` 함수에 Decision Record 5필드 추가
2. `intel-discussion-loop` 크론 프롬프트에 ADR 출력 포맷 강제
3. `apply_intel.js` — 적용 전 ADR 노트 존재 여부 검증 로직 추가

### Phase C: 자동화 연결
1. `pipeline_health_check.js` — 장애 감지 시 Runbook 참조/업데이트 프롬프트 추가
2. 크론 프롬프트 변경 시 Prompt 노트 자동 생성 규칙 (AGENTS.md 레벨)
3. Vault Git hook or 크론으로 "기록 없는 결정" 감사 스크립트
