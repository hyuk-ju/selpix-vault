# 다이내믹 모델 및 사고력(Thinking) 선택 시스템

## 1. 개요 및 철학
OpenClaw 시스템에서 아이디어 검증 시, 단일 모델과 고정된 사고력(Thinking Level)으로 모든 아이디어를 평가하는 것은 비효율적입니다.
새로운 **3단 모드 선택 시스템**은 비용(Cost), 속도(Speed), 분석 깊이(Depth)의 트레이드오프를 사용자가 직접 통제할 수 있도록 권한을 넘겨주는 아키텍처입니다.

## 2. 3가지 모드 체계 (Value Proposition)

### 🚀 스피드 모드 (Spark 기반 / Low Thinking)
- **강점**: 가장 가볍고 빠르며 토큰 비용이 극히 낮습니다.
- **가치**: "이게 수요가 있을까?" 정도의 가벼운 아이디어 파편을 던졌을 때, 트렌드 스카우트 요원(Spark 모델)이 빠르게 트위터/유튜브/온라인 반응만 긁어와서 **도입부와 결론 위주로 즉시 대답**합니다. 기존 Lite 모드를 대체합니다.
- **텔레그램 UI**: `[ 🚀 스피드 (Spark) ]` 버튼 (`idea:spd`)

### ⚖️ 밸런스 모드 (Codex 기반 / Medium Thinking)
- **강점**: 속도와 분석력의 완벽한 균형 (현재 시스템의 표준 모드).
- **가치**: 정식으로 4단계(시장-기술-비즈니스-리스크) 심평을 받으며, DVS(수요검증점수), ICE(기술점수) 등 사전에 정의된 정량적 프레임워크를 성실하게 채워 넣어 점수표(채점 카드)를 완성합니다.
- **텔레그램 UI**: `[ ⚖️ 밸런스 (Codex) ]` 버튼 (`idea:bal`)

### 🧠 딥 다이브 모드 (Codex 기반 / High Thinking)
- **강점**: 압도적인 추론력과 비판적 사고 (High Thinking Token을 공격적으로 소모).
- **가치**: "이건 무조건 해야 해"라고 생각될 만큼 확신이 드는 아이디어를 **가장 엄격하게 까내리고 검증할 때** 씁니다. 단순한 점수 매기기를 넘어, 프리모텀(Pre-Mortem, 사전 실패 분석), 대안 제시, 최악의 시나리오 대비 등 깊은 통찰을 제공합니다.
- **텔레그램 UI**: `[ 🧠 딥 다이브 (High) ]` 버튼 (`idea:deep`)

## 3. 데이터 저장 및 템플릿의 차이

각 모드의 목적과 프롬프트가 다르기 때문에, 에이전트들이 뱉어내는 JSON 데이터의 질(Quality)과 최종 Vault 마크다운(`.md`) 템플릿 형태도 완전히 갈립니다.

### A. 스피드 모드 (Lite 전용 흐름)
- **데이터 필드**: 복잡한 정량 점수(DVS, ICE 계산식 등 50여 개 필드)는 모두 `null`이나 무시 처리됩니다. 오직 `demand`(수요), `competition`(경쟁), `verdict`(판정) 같은 텍스트 필드만 짧게 생성됩니다.
- **최종 마크다운**: 촘촘한 표(Table) 형태의 스코어카드 템플릿 대신, 1~2문단짜리 **"가벼운 요약 카드(Lite Card)" 형태로 Vault에 짧게 저장**됩니다.

### B. 밸런스 모드 (Standard 흐름)
- **데이터 필드**: `_trend.json`, `_tech.json` 등의 파일에 각 담당 에이전트가 마진율, 예상 타겟 일치도, 개발 복잡도 등을 꽉꽉 채워 넣습니다.
- **최종 마크다운**: 기존에 정의된 표 위주의 **정식 스코어카드 템플릿**(`finalizeCard`)으로 Vault에 저장됩니다.

### C. 딥 다이브 모드 (Expert 흐름)
- **데이터 필드**: 밸런스 모드와 똑같은 JSON 스키마 구조를 쓰지만, 안에 들어가는 **'텍스트 길이와 뎁스(Depth)'가 압도적**으로 다릅니다. 특히 치명적 결함(`fatal_flaws`), 대안 제시(`alternatives`), 미검증 가정(`assumptions_unverified`) 같은 리스크 분석 필드가 엄청나게 정교하게 채워집니다.
- **최종 마크다운**: 밸런스와 같은 스코어카드 템플릿을 쓰지만, "악마의 변호인" 섹션과 "리스크 탐지표"의 내용이 매우 길고 논리정연한 글로 렌더링됩니다.

## 4. 시스템 연동 아키텍처

- **라우팅**: 텔레그램에서 버튼 클릭 시 `process_idea.js`가 `--model` 과 `--thinking` 파라미터를 파싱하여 `data/idea_sessions/XXXXXXXX.json` 내 `compute_profile` 객체로 기록합니다.
- **프롬프트 인젝션**: 오케스트레이터(또는 Human Operator)가 하위 에이전트를 스폰(`sessions_spawn`)할 때, `compute_profile` 값을 읽고 **결론 위주로 짧게 쓸지(Low)**, **최대한 딥 다이브하며 논리 전개 과정을 명시할지(High)** 메타 지시어를 덧붙여 행동 양식을 조정합니다 (`AGENTS.md` 지침 참고).
